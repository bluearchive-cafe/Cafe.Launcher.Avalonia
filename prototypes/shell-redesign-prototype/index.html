一个主壳，三条使用路径

这是建议的信息结构；功能归属沿用现有程序集与领域边界。

结构提案 · 待选型
首次使用设置向导语言、路径与必要选项 → 进入主界面
↓
日常入口主界面壁纸 + 游戏状态 + 唯一主要操作 + 可隐藏的公告
01 / 游戏

安装、启动与维护

  • 安装 / 更新 / 选择已有目录
  • 下载、校验与停止确认
  • 启动中 / 运行中 / 失败恢复
  • 管理菜单 → 修复 / 卸载等

操作区随状态切换内容，保持位置连续。

02 / 配置

设置与资源

  • 设置：常规、游戏、下载与网络
  • 设置：外观、高级、关于
  • 资源：UID、资源偏好、批量保存
  • 关闭有草稿的表面 → 放弃确认

设置草稿与资源偏好草稿分别管理。

03 / 支持

更新与故障处理

  • 启动器更新 → 说明、进度与结果
  • 帮助、日志查看与导出
  • 诊断面板（现有 Debug 入口）
  • 独立崩溃窗口 → 日志 / 详情 / 退出

崩溃窗口保持独立进程与资源边界。

共同交互层设置 100 → 对话框 200 → 向导 500 → 向导退出确认 501 → 通知 1000ESC 作用于模态栈顶；关闭后恢复焦点；风险确认与草稿保护保留。

本轮可评估

首页布局、信息优先级、状态连续性、公告降级、浅深主题、壁纸遮挡和文字放大。

下一轮需要真实 Avalonia 验证

原生菜单与焦点、四语言排版、真实 DPI、视频背景、动效和真实业务状态接线。

状态决定界面，而不是追加提示

游戏操作、游戏会话和公告分别建模；公告失败不会把游戏改成故障态。

场景主要信息主要操作 / 次要操作设计约束预览

其他表面的关键状态

设置：已保存 / 有草稿 / 保存失败。资源：无 UID / 加载 / 有草稿 / 提交中 / 失败。更新：加载说明 / 说明失败 / 下载 / 重启。向导：各步骤 / 退出确认。卸载：确认 / 扫描 / 删除 / 残留 / 失败。

评判标准

沿用 ADR-001：可读性、安装/进度/控制三态一致性、壁纸主体遮挡、键盘可达性。可读性不合格直接淘汰。HTML 原型不能证明 Avalonia 已达标。
