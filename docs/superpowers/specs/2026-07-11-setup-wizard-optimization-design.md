# 设置向导优化设计

## 背景

当前首次启动设置向导采用居中弹窗和线性 5 步流程：欢迎与语言、下载源、游戏路径、代理、确认。它已经能完成必要配置，但在界面层级和技术选项解释上仍偏弱：用户不容易判断自己处在哪一步，也不容易理解「下载源」「代理」这类选项为什么要选某一个。

本次优化聚焦向导本身，不改变设置保存、下载、代理或启动流程。

## 目标

1. 将向导改为固定尺寸弹窗，避免步骤切换时窗口随内容跳动。
2. 使用左侧步骤导航展示进度、当前步骤和已完成摘要。
3. 用选择卡片替代技术感较强的单选列表，让选项更易理解。
4. 提供情境化推荐，例如简体中文场景推荐 Cafe 下载源，但不强制用户选择。
5. 保留逐步引导：用户只能回看已完成步骤，不能跳过未完成步骤。

## 非目标

- 不新增设置项。
- 不改变 `LauncherSettings` 的持久化格式。
- 不改变下载源、代理、游戏目录校验的业务规则。
- 不引入新的导航框架或多窗口流程。

## 界面结构

设置向导仍作为首次启动覆盖层显示，但弹窗使用固定尺寸，建议约 `920 × 560`。固定尺寸需在 `MainWindow` 最小高度 `640` 内保留安全边距。

弹窗分为 3 个稳定区域：

1. **Header：** 固定高度，显示「首次设置」标题和简短说明。
2. **Body：** 左侧步骤导航 + 右侧当前步骤内容。
3. **Footer：** 固定高度，显示返回、继续、完成等操作。

只有右侧正文内容允许滚动。Header、左侧导航和 Footer 不随内容滚动。切换步骤时弹窗位置、宽度和高度保持不变。

## 左侧步骤导航

左侧展示 5 个步骤：

1. 语言
2. 下载源
3. 游戏目录
4. 网络
5. 确认

每个步骤有 3 种状态：

- **已完成：** 可点击返回，并显示该步骤摘要，例如「简体中文」「Cafe 下载源」。
- **当前：** 高亮显示，展示当前步骤说明。
- **锁定：** 未完成步骤显示锁定态，不允许跳转。

导航行为采用「仅可回看已完成步骤」。这样用户能修改前面选择，同时仍按向导顺序理解配置项。

## 右侧内容设计

每一步只解释当前决策，避免把多个设置混在同一页。

### 语言

- 使用现有语言选项。
- 用一句说明解释语言只影响启动器界面，不代表游戏内容一定切换。
- 完成后左侧摘要显示选中语言。

### 下载源

- 使用选择卡片呈现 Cafe 和 Official。
- 每张卡片包含标题、简短描述和适用场景。
- 当用户选择简体中文或繁体中文时，Cafe 卡片显示「推荐给你」。
- 推荐 chip 固定在卡片右上角，不能占据标题行前方空间；所有卡片标题与描述从相同位置开始。
- 推荐说明放在卡片上方的提示区，例如：「你已选择简体中文；Cafe 源适合希望使用中文内容的用户。」

推荐只解释原因，不强制改写用户选择。用户仍可选择 Official。

### 游戏目录

- 保留路径输入框和浏览按钮。
- 游戏目录为空时不能继续。
- 说明文案强调此路径会规范化为 `YostarGames\BlueArchive_JP`。
- 路径过长时在输入框和确认摘要中使用截断显示，但保留完整值用于保存。

### 网络

- 使用选择卡片呈现代理模式。
- 文案解释使用场景，而不是只显示技术名词：
  - 直接连接：不使用系统代理。
  - 自动 / 默认：按现有默认策略处理。
  - 系统代理：当下载或刷新受本地网络影响时使用系统代理。
- 不自动检测网络，不新增连通性测试。

### 确认

- 展示 4 项摘要：语言、下载源、游戏目录、网络。
- 每项提供「返回修改」入口，行为等同点击左侧已完成步骤。
- 点击完成后沿用现有 `SettingsApplied` → 保存设置 → 刷新主界面的流程。

## 交互规则

- 初次进入向导时从语言步骤开始。
- 「继续」只前进到下一步。
- 「返回」只返回前一步。
- 左侧只能点击已完成步骤。
- 未完成步骤不能通过左侧跳转。
- 游戏目录为空时禁用「继续」，并显示本地化错误提示。
- 「跳过」保留现有行为：应用默认设置并退出向导。
- 完成后关闭向导，并启动正常初始化 / 刷新流程。

## 视觉规则

- 弹窗固定大小，不随内容自动适应。
- 右侧正文内容使用内部滚动区域。
- 选择卡片高度尽量一致，标题和描述位置统一。
- 推荐 chip 位于卡片右上角。
- 使用现有 `Launcher*` 设计 token，不在 View XAML 中添加裸色值、`Transparent`、裸图标尺寸或裸 4/6/8 圆角。
- 左侧导航、卡片、提示区和 Footer 使用现有主题色与动态资源，支持浅色 / 深色主题。

## ViewModel 调整

`SetupWizardViewModel` 继续负责步骤状态和最终设置输出，但需要补充更适合左侧导航和选择卡片的只读状态：

- 当前步骤索引与总步骤数。
- 每个步骤的完成、当前、锁定状态。
- 每个已完成步骤的摘要文本。
- 可点击返回已完成步骤的命令。
- 下载源与代理推荐状态。

这些状态只描述 UI 所需的投影，不改变 `LauncherSettings` 的模型结构。

## 文件影响

预计修改：

- `Views/SetupWizardOverlay.axaml`：改为固定尺寸、左侧导航和右侧选择卡片布局。
- `ViewModels/SetupWizardViewModel.cs`：补充导航状态、摘要、推荐状态和跳转命令。
- `Assets/Locales/{en,zh-Hans,zh-Hant,ja}.json`：补充新增文案。
- `ViewModels/LocalizedStrings.cs`：补充新增本地化属性。
- `tests/Cafe.Launcher.Avalonia.Tests/SetupWizardViewModelTests.cs`：覆盖新状态和导航规则。
- 如 XAML 合约需要补充，更新相关 UI contract 测试。

## 测试计划

至少覆盖以下场景：

1. 初始状态为第 1 步，后续步骤为锁定态。
2. 完成某一步后，该步骤可从左侧点击返回。
3. 未完成步骤不能通过左侧跳转。
4. 游戏目录为空时不能继续。
5. 简体中文或繁体中文场景下 Cafe 下载源标记为推荐。
6. 推荐 chip 不影响卡片标题与描述的统一布局（通过 XAML 结构或样式合约保护）。
7. 固定弹窗尺寸和右侧滚动区域满足 XAML 样式约束。
8. `CompleteCommand` 仍输出兼容的 `LauncherSettings`。

XAML 或样式改动后运行 `UiStyleContractTests`。实现完成前至少运行受影响的 `SetupWizardViewModelTests` 和相关 headless / style contract 测试。

## 自检结果

- 无占位符或待定项。
- 范围聚焦在设置向导界面和 ViewModel 投影，不涉及下载、代理或设置持久化业务重写。
- 固定尺寸、受限导航、推荐 chip 位置和内容可理解性目标之间没有冲突。
- 所有新增用户可见文案都明确需要进入 4 个 locale 文件。
