# 动效生命周期修复设计

## 目标

修复启动器动效在退出、轮播加载和系统偏好同步方面的不一致，使界面反馈更连贯，同时保持“减少动态效果”的既有语义与用户控制权。

本轮明确不修改 `LoadingOverlay`。完整动态效果与减少动态效果下的加载指示均保持现状。

## 范围

实现以下行为：

1. 覆盖层和 Toast 关闭时播放退出动画，动画结束后才隐藏或移除。
2. 减少动态效果时跳过退出等待，立即隐藏或移除。
3. 退出过程中重新打开同一覆盖层时取消旧退出操作，避免新界面被过期任务关闭。
4. 自动轮播仅在下一张横幅已经加载完成或明确加载失败时前进。
5. 使用“跟随系统”模式时，主窗口重新激活后重新读取 Windows 动画设置。

以下内容不在本轮范围：

- 修改 `LoadingOverlay` 的动画、速度或视觉样式。
- 修改完整动态效果下现有入场动画的持续时间、位移或缓动。
- 新增用户可配置的动画速度。
- 重构与动效无关的对话框、设置或轮播代码。

## 设计原则

- 领域可见状态仍由现有 ViewModel 管理，动画层只延迟视觉元素的最终隐藏，不改变业务状态含义。
- 多个覆盖层复用同一套退出协调逻辑，避免在每个关闭命令中添加 `Task.Delay`。
- 动画等待必须可取消；过期的关闭操作不能影响后续重新打开。
- 自动轮播可以等待内容，不能为了保持节奏而切换到仍在加载的横幅。
- 系统偏好只在窗口重新获得激活时刷新，不引入 Windows 消息钩子或常驻轮询。

## 覆盖层退出生命周期

新增一个面向 Avalonia 控件的轻量可见性行为。行为接收三个输入：

- 业务是否打开；
- 是否启用动效；
- 退出时长，默认使用 `AnimationTimings.ExitAnimationDuration`。

打开流程：

1. 取消尚未完成的退出操作。
2. 立即设置实际可见。
3. 移除退出样式类并应用进入样式类。

关闭流程：

1. 业务状态立即变为关闭，ModalHost 等现有业务协调仍按当前时机工作。
2. 完整动态效果下，视觉元素保持可见并切换到退出样式类。
3. 退出时长结束后，仅当这仍是最新一次关闭请求时，设置实际不可见。
4. 减少动态效果下，不添加退出样式类并立即设置实际不可见。

覆盖层退出期间继续占据最上层并阻挡指针命中，避免背景内容在视觉遮罩消失前被误触。业务焦点恢复仍沿用 ModalHost 的现有行为。

退出样式与现有进入样式保持对应：遮罩淡出，表面轻微下移并淡出；不增加缩放、旋转或大距离位移。

## Toast 退出生命周期

`ToastNotification` 增加可通知界面的退出展示状态。ToastHost 将手动关闭和自动超时统一到同一个异步退出方法：

1. 忽略已经退出或已经移除的 Toast。
2. 完整动态效果下设置退出状态并等待统一退出时长。
3. 减少动态效果下跳过等待。
4. 在 UI 线程从 `ActiveToasts` 删除通知。

宿主销毁时继续使用现有生命周期取消令牌中止等待。重复关闭不会抛出异常，也不会重复删除。

Toast 退出动画采用与入场相反的短距离下移和淡出。退出时长由 `AnimationTimings.ExitAnimationDuration` 提供，测试可以继续将其设置为零。

## 轮播加载门槛

保留现有计时器启动时机。每次 Tick 计算下一张横幅后，先检查其图片状态：

- 图片已加载：允许切换。
- 图片加载失败：允许切换并显示现有失败占位。
- 图片仍在加载或尚未开始：本次不切换。

该门槛仅约束自动轮播。上一张、下一张和圆点选择等用户主动导航继续立即响应，用户主动请求时允许看到加载状态。

此方案不等待全部图片，因此单张慢图不会阻塞其他已就绪横幅，也不改变图片预加载与缓存流程。

## 跟随系统偏好

主窗口激活时通知 MainWindowViewModel 重新评估动效偏好。仅当已保存设置的 `MotionMode` 为 `System` 时读取 Windows 设置；完整和减少模式不进行系统查询。

解析结果与当前 `IsMotionReduced` 不同时才更新状态并通知 RemoteContent，避免每次窗口激活都重建轮播转场对象或重复停止计时器。

读取失败继续沿用当前保守策略：视为需要减少动态效果。

## 错误与并发处理

- 覆盖层的每次打开或关闭产生新的版本；延时结束前验证版本，旧请求自动失效。
- Toast 退出使用同一个生命周期取消令牌，并通过退出状态实现幂等。
- 轮播 Tick 只读取 UI 线程上的集合与图片状态，不增加后台同步原语。
- Windows 偏好读取不抛出平台异常；非 Windows 或读取失败继续返回未知状态。

## 测试策略

遵循测试先行，新增以下回归信号：

1. 覆盖层完整动效关闭后，在退出时长内仍实际可见，结束后隐藏。
2. 覆盖层减少动效关闭时立即隐藏。
3. 覆盖层退出过程中重新打开，不会被旧退出任务隐藏。
4. Toast 手动关闭进入退出状态，等待后才从集合移除。
5. Toast 自动超时与手动关闭共用退出路径且重复请求幂等。
6. 自动轮播在下一张仍加载时保持当前索引。
7. 自动轮播在下一张加载成功或失败后允许前进。
8. 系统模式在窗口激活刷新后更新有效动效状态。
9. 完整或减少模式在窗口激活时不读取 Windows 动画设置。

现有测试项目当前因 `SetupWizardViewModelTests` 缺少 `LocalDiagnostics` 构造参数而无法编译。实施前做最小参数适配，只恢复既有测试构造，不改变设置向导行为。

## 验收标准

- 完整动态效果下，覆盖层和 Toast 关闭过程可见且不会突然消失。
- 减少动态效果下，关闭操作没有人为等待。
- 快速关闭后重新打开不会闪退或被过期退出隐藏。
- 自动轮播不会切换到仍在加载的下一张横幅。
- “跟随系统”在窗口重新激活后反映最新 Windows 动画设置。
- `LoadingOverlay` 文件和行为保持不变。
- 动效相关单元测试、UI 契约测试和 Headless UI 测试通过。
