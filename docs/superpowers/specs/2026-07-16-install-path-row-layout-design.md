# 安装路径操作行布局修复设计

> **后续决策：** “更改路径”按钮的位置已由 `2026-07-16-install-path-inline-action-design.md` 调整为路径字段尾部附属操作；本文关于该按钮必须位于 `path-field` 外部的描述不再适用，其余自适应和可达性约束继续有效。

## 问题

未安装状态下，`path-field` 当前同时包裹路径文本、“更改路径”、“检测”和“安装游戏”按钮。边框因此覆盖整条操作行，使路径输入区域的视觉宽度与实际内容边界不符；窗口收窄或文案变长时，路径文本也会被多个按钮过度挤压。

## 设计

将安装路径操作行改为一个四列 Grid：

1. 第一列为 `*`，只放置现有 `path-field`，其内部保留“路径”标签和可省略的路径文本。
2. 后三列为 `Auto`，依次放置“更改路径”、“检测”和“安装游戏”按钮。
3. 四个区域继续位于同一行，保持已确认的“路径确认后直接安装”操作顺序。
4. 列间距复用现有 `LauncherSpacingSm`；不设置固定宽度、不新增颜色、文案、绑定或 ViewModel 状态。

路径框占用按钮之外的全部剩余宽度。窗口缩小时，路径文本通过现有 `CharacterEllipsis` 截断，按钮保持其内容所需宽度和既有可访问性名称。

## 影响范围

- 仅修改未安装面板的 `Views/MainWindow.axaml` 布局层级。
- 保留现有命令、启用状态、Tooltip、AutomationProperties 和样式类。
- 不改变进度面板、已安装控制面板、远程接口或持久化设置。

## 验证

- 新增契约测试：`path-field` 不再包含任何按钮；三个操作按钮与路径框同属外层操作行。
- 新增或调整 headless 测试：默认宽度和最小窗口宽度下，路径框具有正宽度且不与按钮重叠，所有按钮位于窗口内。
- 运行 `dotnet test` 的相关契约/headless 用例及 `./dev.ps1 ui`。
