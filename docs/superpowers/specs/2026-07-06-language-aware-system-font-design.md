# 按界面语言切换系统字体

## 目标

在不嵌入字体文件、不增加发布体积的前提下，为英语、简体中文、繁体中文和日语界面选择对应的 Windows UI 字体，使文字字形与界面语言一致，并保留现有排版层级和字重令牌。

## 字体映射

字体家族名称必须使用 Windows 字体注册表中的精确名称：

| 界面语言代码 | 全局字体家族 |
|---|---|
| `en` | `Segoe UI` |
| `zh-Hans` | `Microsoft YaHei UI` |
| `zh-Hant` | `Microsoft JhengHei UI` |
| `ja` | `Yu Gothic UI` |

`auto` 不单独定义字体。它先由现有本地化逻辑解析为上述四个语言代码之一，再使用解析结果选择字体。

## 应用方式

新增集中管理的语言字体映射，输入为本地化服务已经解析出的有效语言代码，输出为 `FontFamily`。映射不执行大小写、格式或别名匹配；无法识别的值按现有语言规范化流程处理，不在字体映射中增加第二套推断规则。

根窗口设置全局 `FontFamily`，所有未显式指定字体的后代控件通过 Avalonia 属性继承使用该字体。初始化界面语言及运行时切换语言时，使用同一条应用语言流程同步更新根窗口字体，不重新创建窗口。

现有显式字体保持不变：

- 日志查看器继续使用 `LauncherFontFamilyMonospace`，其值为 `Consolas`。
- Material 图标继续使用图标控件自身的字体资源。

移除 `.WithInterFont()`，避免 Inter 继续成为默认字体并对中日韩字符触发系统回退。`Avalonia.Fonts.Inter` 包在确认无其他引用后移除。

## 字重

保留现有两个字重令牌：

- `LauncherFontWeightNormal`：`Normal`
- `LauncherFontWeightStrong`：`SemiBold`

本次不扩大强字重的使用范围，也不把 `SemiBold` 改为 `Bold`。字体家族切换与排版层级调整分开处理，防止无法判断视觉变化来自字体还是字重规则。

## 验证

自动化验证覆盖：

1. 四个语言代码映射到表中精确的字体家族名称。
2. `auto` 使用本地化服务解析后的语言代码，不直接进入字体映射。
3. 打开设置界面后，可见文本继承当前语言对应的根窗口字体。
4. 运行时切换四种语言时，根窗口字体同步切换。
5. 日志文本仍使用 `Consolas`。
6. `Avalonia.Fonts.Inter` 没有引用后，从项目依赖和 `Program.cs` 中移除。
7. Debug 构建、单元测试、无头测试和 Release 构建全部通过。

## 平台约束

项目现有运行环境为 Windows。该方案依赖 Windows 随系统提供的四个字体家族，不引入字体下载、字体安装或运行时网络访问。
