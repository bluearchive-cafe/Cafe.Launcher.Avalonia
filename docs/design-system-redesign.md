# 启动器设计系统简化与视觉重设计

## 状态

本设计的决策已经收敛。HTML 视觉稿验收与 Avalonia XAML 实施尚未包含在本文档工作中。

实施顺序固定为：

1. 制作并验收 HTML 视觉稿。
2. 视觉方向确认后，一次性替换 Avalonia XAML 与内部样式 API。
3. 重写 UI 契约测试并完成针对性验证。

当前工作区中未提交的设置重构是设计基线。后续工作不得回退或覆盖这些修改。

## 背景

当前设计系统的主要问题不是缺少 token，而是设计决策表面积过大：

- `App.axaml` 定义 137 个唯一资源键，其中约 50 个只使用一次。
- 全项目约有 249 个 Style selector，`MainWindow.Styles.axaml` 独占约 196 个。
- `UiStyleContractTests.cs` 包含约 100 个测试，并大量锁定具体 class、setter 和 token 数值。
- Toast、日志窗口、调试窗口等功能尺寸被提升为全局 token，模糊了基础设计规则和页面布局参数的边界。
- 多个页面通过叠加大量 class 表达布局位置、组件外观和业务语义，导致样式难以理解和安全修改。

本次工作既要重新建立视觉方向，也要收缩全局抽象，让新增界面有少量且明确的选择。

## 目标

- 建立沉浸式游戏启动器视觉，突出角色背景和唯一主操作。
- 保留 Avalonia `FluentTheme` 提供的成熟控件行为，只维护一层精简的 Cafe 视觉语义。
- 将基础尺度、主题颜色、共享组件和功能布局分开管理。
- 删除一次性全局 token 和不稳定的样式组合。
- 保留浅色与深色主题、动态强调色、减少动画、键盘与自动化可访问性、本地化及窗口缩放能力。
- 将设置改为即时生效、自动保存的直接操作模型。
- 让测试保护产品行为和设计约束，而不是锁定 XAML 的具体写法。

## 非目标

- 不建设供其他 Cafe 应用消费的公共组件库。
- 不采用 Material Design 3，也不完全自绘 Avalonia 控件。
- 不改变除设置保存方式以外的业务流程。
- 不长期保留新旧设计系统兼容层。
- 不以总代码行数、token 数量或 selector 数量的固定削减比例衡量成果。
- 不让设计系统依赖某一张背景图才能成立。

## 设计原则

### 一个清晰的主操作

开始、安装、更新和继续等状态共享同一个主操作位置和组件外观。页面不能同时出现多个视觉权重相同的主按钮。

### 内容资产不是设计依赖

现有 Blue Archive 背景作为默认内容继续使用，但所有文字、表面和交互状态必须在任意合法背景下保持可读。主题相关遮罩和半透明表面负责稳定对比度。

### 结构复用优先于外观封装

重复结构、行为或可访问性逻辑可以成为 `UserControl`。纯视觉差异使用 Style；不能为每种按钮、卡片或页面片段创建控件。

### 全局 token 必须拥有稳定消费者

只使用一次、只描述某个页面尺寸或没有跨组件语义的数值不能成为全局 token。功能布局参数留在对应功能样式中。

### 可访问性是能力，不是主题变体

主题切换、强调色变化和动画设置不能削弱键盘操作、焦点提示、自动化名称或文字对比度。

## 视觉基础

### 控件基础

- 继续使用 Avalonia `FluentTheme`。
- 继续统一使用 `Material.Icons.Avalonia`。
- 不混入第二套图标库。
- 图标尺寸仅保留 `16 / 20 / 24`。

### 视觉性格

整体采用沉浸式游戏启动器风格：

- 背景和角色是主舞台，而不是卡片网格的装饰。
- 深色主题使用深海军蓝表面和强调色高光。
- 浅色主题继续显示角色背景，并使用明亮半透明表面及对应遮罩。
- 玻璃感通过半透明纯色、细边框和静态渐变实现，不使用实时 Blur 或 Acrylic。
- 主界面相对宽松；设置、日志和调试等工具区域保持紧凑。

### 尺度

| 类别 | 允许值或角色 |
| --- | --- |
| 间距 | `4 / 8 / 12 / 16 / 24 / 32` |
| 圆角 | 小 `6`、中 `10`、大 `16` |
| 图标 | `16 / 20 / 24` |
| 排版 | `Caption / Body / Label / Title / Display` |
| 动画 | 快速反馈、内容进入、模态表面 |

页面通过排版角色使用字体，不直接引用一组不断扩张的字号 token。语言相关字体仍由现有字体服务解析。

### 主要操作

- 使用当前强调色的实心表面。
- 高度约为 `52px`，采用中等圆角。
- 正常情况下只显示一个主操作。
- Hover、Pressed、Disabled 和 Focus 状态来自同一语义色阶。
- 不使用大胶囊形、发光外圈或页面专属主按钮样式。

### 强调色

以下四种强调色来源全部保留：

- 默认品牌色
- 操作系统强调色
- 壁纸取色
- 用户自定义色

默认品牌色固定为 `#FF2E7DF6`，不得在重设计中改变。该基础色的 Hover、Pressed、Soft 和 OnPrimary 等派生颜色可以由新的可访问性色阶算法生成。

当前解析出的强调色统一驱动所有主操作和强调状态。解析流程必须：

1. 取得当前模式的基础颜色。
2. 规范化颜色并生成交互色阶。
3. 为强调色表面选择满足对比度要求的前景色。
4. 为浅色和深色主题提供稳定的 Soft、Border 和 Focus 语义色。

## 主窗口

### 总体结构

```text
┌──────────────────────── 精简透明标题栏 ────────────────────────┐
│ 产品标识                   资源面板  设置  更多  最小化  关闭 │
├──────────────────────────────────────────────────────────────┤
│ ┌──── 左侧内容栏 ────┐                        社交图标栏 ┐    │
│ │ 重要公告           │                                     │
│ │ 横幅               │          角色与背景主舞台           │
│ │ 新闻摘要           │                                     │
│ └────────────────────┘                                     │
├──────────────────────── 底部操作坞 ─────────────────────────┤
│ 状态与关键信息                         次要操作   主操作     │
└──────────────────────────────────────────────────────────────┘
```

### 标题栏

- 使用透明、精简的自定义标题栏。
- 左侧保留小型产品标识和足够的窗口拖动区域。
- 右侧直接保留资源面板、设置、最小化和关闭。
- 调试入口移入“更多”菜单；资源面板不移动。
- 标题栏不再承担状态摘要或普通功能导航。

### 左侧内容栏

- 标准窗口下宽度约 `400–440px`。
- 顶部显示一条重要公告。
- 横幅和新闻成为两个独立模块。
- 新闻默认只显示三条摘要。
- 不将全部远程内容重新堆进一个长滚动面板。

### 横幅

横幅默认只显示图片，不永久展示按钮、页点或工具栏。

鼠标悬停时：

- 图片两侧显示上一张和下一张按钮。
- 底部中央显示当前页点。
- 控件使用覆盖式渐变遮罩保证可读。

键盘行为：

- 内部按钮不加入 Tab 顺序。
- 整张横幅作为一个可聚焦链接。
- 左右方向键切换横幅。
- 空格切换暂停与播放。
- Enter 打开当前横幅链接。
- 键盘聚焦不显现内部鼠标控件。

自动轮播行为：

- 默认每 6 秒切换。
- 鼠标进入横幅时暂停，离开后重新计时。
- 窗口失去活动状态时暂停。
- 启用“减少动画”时不自动轮播。
- 切换不能抢占焦点，也不能播报非当前内容。

### 社交入口

- 在窗口右上区域垂直显示图标栏。
- 图标栏始终可见但保持低视觉权重。
- 悬停显示入口名称。
- 使用独立半透明底板，不依赖背景明暗。
- 紧凑窗口下收进“更多”菜单。

### 底部操作坞

- 左侧只显示状态标题和一行关键信息。
- 右侧固定唯一主操作。
- 路径、刷新和官网等入口作为次要操作，不与主按钮争夺视觉权重。
- 下载或修复时，操作坞原位切换为进度、速度、剩余时间及暂停/停止。
- 不为普通、安装、下载和启动状态维护多套重复布局。

### 紧凑窗口

应用继续支持 `1024×640`：

- 左侧内容栏折叠为可展开抽屉。
- 底部操作坞始终可见。
- 次要入口允许收进更多菜单。
- 设置内容滚动并让控件换行。
- 不等比缩小字号、点击区域和全部布局尺寸。

## 设置

### 容器与导航

- 设置继续使用大型居中模态层。
- 标准窗口下保留左侧分类、右侧内容结构。
- 紧凑窗口下模态层使用统一安全边距填满可用区域。
- 设置拥有自己的极简标题栏，只保留“设置”、必要的未同步状态和关闭按钮。
- 删除标题图标、启动器状态摘要以及底部 Save/Cancel 操作区。

### 设置行

- 删除每一行的装饰图标。
- 图标只用于分类、危险操作或确有必要的状态表达。
- 使用分组标题、平坦设置行和细分隔线。
- 不给每一项设置套独立卡片。
- 宽窗口下标题与说明在左、控件在右。
- 空间不足时控件换到下一行并占满可用宽度。

### 即时生效与自动保存

设置不再维护用户可见的事务式 Save/Cancel 会话。

```text
用户修改
   ↓
立即更新 UI/运行时状态
   ↓
重启约 400ms 合并保存计时
   ↓
规范化设置 → 原子写入临时文件 → 替换设置文件
   ├─ 成功：安静完成
   └─ 失败：保留当前值、标记未同步、提供重试
```

具体规则：

- 语言、主题、强调色、背景、动画和日志级别立即应用。
- 代理、下载限速和更新通道等影响下一次新操作，不中断正在运行的下载。
- 游戏路径通过现有验证并成功选择后才保存。
- 卸载、清理日志和恢复默认等命令仍需明确触发；危险操作继续确认。
- 连续修改在最后一次变化后约 400ms 合并写入。
- 关闭设置或退出应用时强制完成待写入。
- 设置界面可以立即关闭，写入在后台完成。
- 成功保存通常不显示 Toast；只有写入异常变慢时才显示进行状态。
- 失败时不自动回滚当前 UI，而是显示持久错误和“重试保存”。
- 只提供一个全局“恢复默认设置”，确认后立即应用并保存。

## 模态层、工具与通知

### 尺寸体系

模态层只保留两档：

- 小型：确认、警告和简短输入。
- 大型：设置、资源面板、日志、调试和设置向导。

内容决定是否滚动。日志宽度、调试窗口高度等不再成为全局设计 token。

### 工具面板

- 资源面板、日志和调试共用精简标题栏及内容框架。
- 设置使用单独的即时保存设置框架，不强行与工具面板共用。
- 工具区域保持紧凑和弱装饰，不复制首页的沉浸式表现。

### 设置向导

- 使用大型模态层。
- 左侧为紧凑步骤轨道。
- 右侧为当前步骤内容。
- 底部固定上一步和下一步。
- 步骤轨道属于向导功能，不提升为全局组件。

### 确认框

- 次要或取消操作在左，确认操作在右。
- 危险确认使用危险语义色。
- 默认焦点位于安全操作。
- 普通确认与危险确认共享结构，只改变语义和默认焦点。

### Toast

- 保持当前右上位置。
- Toast 可以临时覆盖右上社交入口，不移动或隐藏社交栏。
- 保留标题、消息、关闭及最多两个操作。
- 删除自动消失进度条。
- 执行 Toast 操作时仍可显示进度状态。
- 自动消失继续由时长管理。

## 设计系统架构

### 文件职责

```text
App.axaml
└─ 只组合主题、基础资源和共享样式

Foundation.axaml
├─ 间距
├─ 圆角
├─ 排版角色
└─ 动画词汇

Theme.axaml
├─ Light 语义颜色
├─ Dark 语义颜色
└─ 当前强调色色阶

Controls.axaml
├─ Button
├─ 输入控件
├─ 通用 Surface
└─ 共享视觉状态

功能 *.Styles.axaml
├─ 页面布局
├─ 页面专属尺寸
└─ 功能状态
```

最终文件位置可以遵循现有 `Views/Styles/` 组织，但职责边界不得重新混合。

### 资源命名

资源使用分层名称：

- `Cafe.Space.2`
- `Cafe.Radius.Medium`
- `Cafe.Type.Body`
- `Cafe.Color.Surface`
- `Cafe.Color.OnSurface`
- `Cafe.Motion.Fast`

资源名称表达设计层级和语义，不能包含 Toast、日志窗口或具体页面名称。

### Style class

使用控件基类和少量视觉变体：

```text
Button.primary
Button.quiet
Button.danger
Border.surface
Border.surface.elevated
```

禁止重新出现同时表达组件、页面位置和业务操作的长 class 组合，例如：

```text
primary-action bottom-action path-operation primary-operation
```

页面定位由布局负责；视觉 class 只表达组件变体。

### 共享控件边界

| 对象 | 实现方式 | 原因 |
| --- | --- | --- |
| `SettingRow` | 共享结构控件 | 统一响应式布局、说明和操作区 |
| `SettingComboRow` | 共享结构控件 | 重复结构及选择绑定约束 |
| 对话框框架 | 共享结构控件 | 统一标题、关闭、滚动、操作区和焦点行为 |
| `LoadingOverlay` | 共享状态控件 | 重复加载结构和可访问性行为 |
| Button、Card、Typography | Style | 只有视觉差异 |
| Toast 外观 | Style | 状态和生命周期由现有宿主管理 |
| 横幅、新闻、操作坞 | 功能私有 | 属于特定页面和业务状态 |

## 仓库规则调整

项目指南需要同步改为：

- View 中不得硬编码颜色。
- 间距优先使用六档基础尺度。
- 页面专属宽高、网格尺寸和安全边距可以留在功能样式中。
- 只使用一次且没有跨组件语义的数值不得提升为全局 token。
- 例外必须有明确的控件、布局或可访问性理由。

这项调整用于阻止“为了消除字面量而创建一次性 token”的循环。

## 测试策略

删除或重写锁定具体 class、setter 和精确 token 数值的测试。新的测试主要保护：

- Light 和 Dark 主题拥有完整语义颜色集合。
- View 中没有裸颜色。
- 共享控件拥有 Hover、Pressed、Disabled 和 Focus 状态。
- 主要操作唯一且位置稳定。
- 键盘、自动化名称和焦点行为可用。
- 减少动画能够关闭自动轮播和非必要位移动画。
- `1024×640` 下关键操作仍可访问。
- 设置即时应用、合并保存、失败重试和退出刷新行为正确。
- 核心模态层、Toast 和操作坞保持正确层级。

不为 token 数量、selector 数量或文件行数设置固定削减比例。每个全局抽象都必须能说明其多个稳定消费者。

## HTML 视觉稿

视觉稿存放在 `docs/design-system-prototype/`。各页面是独立 HTML 入口，但共享同一套 CSS token，并允许使用 CSS/JavaScript 表达必要的 Hover 和局部状态。

需要交付五页：

1. 深色首页：普通状态及横幅悬停状态。
2. 深色首页：下载进度状态。
3. 浅色设置：即时保存及未同步错误状态。
4. 紧凑首页：`1024×640`，内容抽屉收起。
5. 组件总览：颜色、排版、按钮、字段、卡片、Toast、确认框以及长英文和日文样例。

页面主要使用简体中文。视觉稿必须使用现有默认背景和 `#FF2E7DF6` 默认强调色，同时证明更换背景、主题和强调色后设计仍然成立。

## HTML 验收门槛

进入 XAML 实施前必须由项目所有者确认：

- 首页主舞台、左侧内容栏和底部操作坞的层级正确。
- 横幅默认纯图片，鼠标悬停和键盘行为符合定义。
- 浅色与深色主题均可读，默认强调色未改变。
- 设置界面足够精简，并明确表达即时保存和失败状态。
- `1024×640` 紧凑布局不隐藏关键操作。
- 组件页能够覆盖实际应用需要的共享视觉，而没有引入页面专属组件。

未经视觉稿确认，不开始一次性 XAML 替换。

## 最终验收

- `App.axaml` 成为清晰的资源组合入口。
- 基础、主题、共享控件和功能布局职责分离。
- 默认强调色保持 `#FF2E7DF6`。
- 四种强调色来源、浅色/深色主题和减少动画全部正常工作。
- 主窗口、设置、工具面板、向导、确认框和 Toast 使用统一视觉语言。
- 设置自动保存没有丢失更新、写入风暴或静默失败。
- 旧内部资源 API 和无价值的精确 XAML 测试被删除，不保留长期兼容层。
- 相关单元测试、Headless UI 测试、UI 样式契约、Debug 构建和完整验证均通过。
