### 文件任务仲裁、暂停、取消与恢复

**源码事实。** RPC 服务维护多任务字典与一个 `CurrentTask`。新任务遇到现有当前任务会进入 `Queueing`；继续某个已有任务可以把当前任务取消到 `Queueing`，然后立刻切换 `CurrentTask` 并弃等启动新执行。任务结束/取消后，`ChangeToAnotherTask` 从字典找一个非暂停、非错误任务继续；它没有显式 FIFO 顺序。下载内部又可用 `Parallel.ForEachAsync` 并行处理文件。这是“名义单当前文件任务 + 等待任务”，不是“全局只能拥有一项任务”。[仲裁，第 99–155 行](https://github.com/Scighost/Starward/blob/df8ae07b5ad4c9c6cb70d288488ce8073ce01478/src/Starward.RPC/GameInstall/GameInstallService.cs#L99-L155)、[交接，第 295–310 行](https://github.com/Scighost/Starward/blob/df8ae07b5ad4c9c6cb70d288488ce8073ce01478/src/Starward.RPC/GameInstall/GameInstallService.cs#L295-L310)、[文件内并行，第 344–365 行](https://github.com/Scighost/Starward/blob/df8ae07b5ad4c9c6cb70d288488ce8073ce01478/src/Starward.RPC/GameInstall/GameInstallService.cs#L344-L365)（本地均为 `E:\Repos\_GameLauncher_Samples\Starward\src\Starward.RPC\GameInstall\GameInstallService.cs`，起始行 99、295、344）。

**源码事实。** 暂停通过上下文 CTS 请求取消并记录 `Paused`，停止则移除字典并记录 `Stop`；执行栈捕获取消后才把状态变成 `CancelState`，随后调用自动交接。因此暂停不会占住全局执行位置，可以让另一个排队任务启动。恢复复用上下文已有 `TaskFiles`，取消过的 CTS 会重新创建；已经完成的文件有内存 `IsFinished` 标记。[暂停/停止，第 165–197 行](https://github.com/Scighost/Starward/blob/df8ae07b5ad4c9c6cb70d288488ce8073ce01478/src/Starward.RPC/GameInstall/GameInstallService.cs#L165-L197)、[捕获取消，第 274–285 行](https://github.com/Scighost/Starward/blob/df8ae07b5ad4c9c6cb70d288488ce8073ce01478/src/Starward.RPC/GameInstall/GameInstallService.cs#L274-L285)（本地：`E:\Repos\_GameLauncher_Samples\Starward\src\Starward.RPC\GameInstall\GameInstallService.cs:165`、`:274`）；[CTS，第 151–173 行](https://github.com/Scighost/Starward/blob/df8ae07b5ad4c9c6cb70d288488ce8073ce01478/src/Starward.RPC/GameInstall/GameInstallContext.cs#L151-L173)（本地：`E:\Repos\_GameLauncher_Samples\Starward\src\Starward.RPC\GameInstall\GameInstallContext.cs:151`）。

**源码事实。** 磁盘续传证据与会话恢复是两回事：普通包下载使用目标旁的 `_tmp` 文件长度发 Range 请求，下载完成校验 MD5 后移动；chunk 下载也在目标安装目录使用 `_tmp` 与 `chunk/<id>` 缓存，按已有长度及哈希复用数据。所读任务服务/上下文没有任务列表或上下文的磁盘序列化；仅凭这些路径不能宣称重启后自动恢复任务或恢复所有阶段。[包续传，第 511–568 行](https://github.com/Scighost/Starward/blob/df8ae07b5ad4c9c6cb70d288488ce8073ce01478/src/Starward.RPC/GameInstall/GameInstallHelper.cs#L511-L568)、[chunk 复用，第 316–367 行](https://github.com/Scighost/Starward/blob/df8ae07b5ad4c9c6cb70d288488ce8073ce01478/src/Starward.RPC/GameInstall/GameInstallHelper.cs#L316-L367)（本地：`E:\Repos\_GameLauncher_Samples\Starward\src\Starward.RPC\GameInstall\GameInstallHelper.cs:511`、`:316`）。

### 对 Cafe 的适用结论

| 观察到的模式 | Cafe 中的取舍 |
| --- | --- |
| 页面参数指向目标，后台单例持有任务与进度 | 保留；切换只切视图，操作捕获独立不可变上下文 |
| 单 CurrentTask 外加按 GameId 的队列；暂停后自动换任务 | 不采用；全局一个文件任务、暂停占位、无队列 |
| Cancel 后立刻切换/替换，卸载等待固定时间 | 不采用；必须等待真正终结后释放所有权 |
| GameId 可写且按 Id 哈希，路径按 biz | 不采用可变身份；统一稳定 gameId，避免页面改字典键 |
| 设置在全局数据库中以目标后缀分区 | 仅借鉴目标归属；仍用版本化 settings.json 的 games 映射及按 gameId 的检查点 |
| 多游戏进程列表独立于选中页面 | 借鉴生命周期分离；进程归属应按 Cafe 的目标语义判定 |
| 隐藏/最小化不取消，真正退出没有统一任务屏障 | 前者一致；后者不能采用，退出确认停止并保留续传 |
| 自更新自行重启/kill 父进程 | 不采用；应用前阻止文件任务与脏草稿 |
| 命令/URL 携带 biz，但在单实例注册前直接启动 | 借鉴显式目标；不能借此证明已有窗口目标转发已完成 |
| 内置能力表并辅以远程目录 | 只借鉴能力表；游戏清单继续内置，无插件 |

这些取舍是对上述静态证据与 Cafe 已给定设计的比较，不是对 Starward 运行正确性的整体评价。未验证网络重试、安装/更新各阶段的崩溃一致性、实际 UI 模态屏蔽、多游戏组合兼容、自更新中的文件锁行为，以及任何第三方/原生依赖内部行为。
