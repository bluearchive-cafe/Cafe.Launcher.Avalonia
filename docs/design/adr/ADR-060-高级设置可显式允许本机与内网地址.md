# ADR-060: 高级设置可显式允许本机与内网地址

- 状态：已接受（2026-11-12）
- 相关：ADR-028（客户端偏好按使用时机拉取）、`AUD-SEC-001`、`AUD-SEC-006`

## 背景

启动器的出站 URL 校验（SSRF 防护）要求 DNS 解析结果为公网地址，本机与内网应答一律拒绝，并把拒绝标记成可行动的 hosts/代理指引。这条规则保护的是「远程内容把请求引向用户本机服务」的一类风险，但它与一类合法使用场景直接冲突：FastGithub、Watt Toolkit 等 GitHub 加速器通过 hosts 把 GitHub 域名改写为 `127.0.0.1`，由本机服务完成代理转发。加速器正常工作时，启动器看到的解析结果必然是本机地址。

[#33](https://github.com/bluearchive-cafe/Cafe.Launcher.Avalonia/issues/33) 即此场景：用户开启加速器后更新下载全部失败，即使重启也无法恢复，只能手动清理 hosts 或关闭加速器。此前的修复只把笼统的网络提示换成 hosts/加速器指引，环境本身仍需用户自行处理；偏好这类加速器的用户在日常更新路径上没有可用选项。

## 决策

1. 设置-高级新增「网络兼容」分组，内含默认关闭的「允许本机或内网地址」（`allowBlockedNetworkAddresses`）。
2. 开关开启后，出站校验只跳过「DNS 解析结果必须是公网」这一条判定，并在解析之前返回。scheme、userinfo、非 80/443 端口、`localhost` 名字与字面 IP 地址的拒绝保持不变——hosts 型加速器改写的是域名解析，不需要放宽这些形状检查。
3. 更新与游戏下载共用同一个校验器，开关对两者同时生效；表现层不改：关闭时既有的拒绝标记与提示保持原样。
4. 开关属于已保存设置，由组合根的一次闭包按使用时机读取（ADR-028）。保存后下一次请求生效，不需要重启，也没有调用方需要推送偏好。
5. 风险登记为 `AUD-SEC-008`：这是用户显式接受的放宽，默认不改变既有防护。

## 未采用

- **始终允许本机地址**：默认暴露会让恶意远程内容无需用户同意即可访问本机 80/443 服务，与 AUD-SEC-001 的取舍相悖。否决。
- **检测加速器进程后自动放行**：进程识别不可靠（同名进程、便携版、服务形态各不相同），且需要枚举用户进程，超出该项收益。否决。
- **只改进提示、不放宽校验**：对 #33 场景的结果仍是「更新不可用」，与本项要解决的问题不符。已按此方向完成过提示改进，作为关闭状态下的体验保留。
- **连字面地址与 `localhost` 名字一并放宽**：加速器不使用字面地址，放宽只会扩大可访问面。否决。

## 后果

- 默认行为不变：关闭时所有既有拒绝与提示逐字保留。
- 开启期间的请求仍受 GET-only、80/443 端口与跨主机重定向剥离凭据的约束（AUD-SEC-001、AUD-SEC-006），但可访问本机或内网的 80/443 服务；用户需在设置说明中看到这一代价。
- 该模式下校验不再解析 DNS，Fake-IP 解析的失败标注（`IsFakeIpResolution`）在此路径上不可用；其只服务于失败归因，不影响请求本身。
- 设置键、术语与用户文档（中英文）同步新增；`settings-advanced-zh` 基准图随新分组重新生成。
