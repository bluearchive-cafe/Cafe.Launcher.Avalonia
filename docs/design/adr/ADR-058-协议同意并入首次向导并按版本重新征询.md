# ADR-058: 用户协议与隐私政策并入首次设置向导并按版本重新征询

- 状态：**已接受**（2026-11-10；协议步骤版式部分于 2026-11-11 由 [ADR-059](ADR-059-设置向导统一舞台与双栏解剖.md) 取代，门禁与版本契约保留）

此前启动器只在设置页提供隐私政策外链，首次启动没有协议同意记录；仓库根目录虽已维护 `TERMS.md` 与 `PRIVACY.md`，但应用内没有门禁。决定把协议同意并入现有首次设置向导：在语言步骤之后新增「用户协议与隐私政策」步骤，内嵌两份仓库文档，滚动至底部后才能勾选并继续。邀请（同意）版本写入 `settings.json` 的 `acceptedAgreementVersion`，已落盘版本与当前 `LauncherAgreement.CurrentVersion` 不一致时，常规启动只显示协议步骤，同意后保留原设置并完成初始化。

## 决策

- 协议正文以仓库根目录的 `TERMS.md`、`PRIVACY.md` 为单一来源，构建期作为 Avalonia 资源嵌入；中文版本为正文，界面用本地化提示说明这一点。
- 协议步骤是硬门禁：未读到文档底部时复选框禁用，未勾选时「下一步」禁用，「跳过引导」隐藏。未同意时确认退出会直接关闭启动器，不会应用默认设置继续运行。
- 首次向导完成或跳过（仅限已同意）时写入当前版本；设置页恢复默认保留已落盘的同意版本，不因重置偏好而撤销同意。
- 版本更新后的重新征询复用同一向导，但只显示协议步骤（进度 `1 / 1`、无上一步与跳过），完成后按原设置克隆写回版本号，不重新归一化游戏路径等字段。
- 版本检查发生在常规启动的完整初始化之前：先生效已保存的窗口几何与语言，再决定是否显示协议步骤；同意或版本已是最新后才进入原有初始化与命令行启动流程。

## 未采用

- 独立启动前协议窗口：与既有向导重复，新增表面与模态接线，且首次与版本更新两条路径难以共用。
- 只落盘布尔值：协议更新后无法重新征询用户。
- 仅保留设置页外链：没有可验证的同意记录，也无法在首次启动阻断主界面。

## 后果

- `LauncherSettings` 增加 `acceptedAgreementVersion`（DeepClone 与状态同一性表同步），设置 JSON 字段集合测试更新。
- `SetupWizardViewModel` 增加协议步骤状态、完成/跳过规则、重新征询模式与退出事件；步骤从 5 步变为 6 步，审阅页回跳索引与样式/无头/golden 契约同步。
- 协议文本或版式变更时，必须同时递增 `LauncherAgreement.CurrentVersion`，否则旧同意不会重新征询。
- 用户文档（首次设置、跳过与退出行为）与 [CONTEXT.md](../../../CONTEXT.md) 的向导契约随本决策更新。

## 修订（2026-11-11）：协议步骤并入统一双栏舞台

单列纵向堆叠（标题、说明、文档、勾选、提示、版次）在下限 920×480 的面板里超出内容视口：步骤被滚动容器垂直居中，标题在首屏被裁掉，文档与提示各引出一次滚动，版次与提示落到折叠线以下。中间设计曾探索「左侧文档阅读器 + 右侧固定宽同意栏」双卡解剖，但未进入任何提交，合入前由 [ADR-059](ADR-059-设置向导统一舞台与双栏解剖.md) 取代；因此 ADR-058 不记录双卡样式令牌，`Agreement.Content.MaxWidth`、`Sidebar.Width` 等键从未落地。

实际落地的协议步骤与其余五步共用五段表面与 300 左引导 + 右面板解剖：版次胶囊与语言声明移入左引导，右面板为 `AgreementScrollViewer`（唯一滚动区）加固定底栏同意项，勾选下方的滚动提示退为 `AutomationProperties.HelpText`；文档正文以 `Launcher.Typography.FontFamily.Document` 钉住 CJK 字族，不随界面语言继承拉丁字体栈。硬门禁语义不变：滚动判定仍由 `AgreementScrollViewer` 到达底部触发，复选框未解锁时「下一步」禁用、「跳过引导」隐藏。协议步骤的版式令牌、样式契约与 golden 由 ADR-059 统一记录。本问的同意门禁、版本重询与 `acceptedAgreementVersion` 契约全部不变。
