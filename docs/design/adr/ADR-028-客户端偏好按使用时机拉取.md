# ADR-028：客户端偏好按使用时机拉取，工厂不再接受偏好推送

- 状态：✅ 已接受
- 日期：2026-09-15
- 来源：架构深化评审（第二轮 · 2026-09-14）候选 13
- 相关：ADR-021（保留操作后端接缝）、ADR-025（数据根注入）、ADR-027（策略判定结果）

## 背景

`HttpClientFactory` 是池化客户端策略的所有者，但它只管「租约 ＋ 连接级默认值」，客户端偏好由外部推送：`ConfigureHttp2(bool)` 写一个字段，`SettingsViewModel`（用户保存设置后）与 `LauncherCoreService`（每次状态加载开头）各推一次。同一族策略的另一半——代理模式——却是拉取的：组合根把 `() => settingsEditor.GetSavedSnapshot().ProxyMode` 注入传输，使用时才解析。

不对称造成两件事：

1. **新调用方必须记得推。** 不推不会报错，只会让租约沿用旧开关——一个只能靠评审发现的失配。
2. **启动期有一段默认值窗口。** 字段默认 `true`，首次推发生在 `LauncherCoreService.LoadAsync` 内部；启动路径先播种设置编辑器（`ShellLifecycle.cs:230`）再调 `LoadAsync`（`:242`），所以在那之前创建的租约一律协商 HTTP/2，哪怕用户保存的是关闭。

实测的写入方是 2 个（两处推送），不是「三个」；代理那边是 1 个读取方。真正的缺陷是推拉不对称，不是写入方数量。

## 决策

1. `HttpClientFactory` 的构造器接收偏好来源：`HttpClientFactory(ProxySettingsService, Func<bool>? enableHttp2Preference = null)`，缺省为 HTTP/2 开启；`ApplyHttpVersion` 在每次租约创建时求值。`ConfigureHttp2` 删除——工厂的公开面只剩租约。
2. 组合根传一次闭包，与代理模式同源：`() => settingsEditor.GetSavedSnapshot().EnableHttp2`。
3. `SettingsViewModel` 与 `LauncherCoreService` 丢掉工厂依赖——两处都只用于那次推（核过：设置页不做任何出站工作；核心服务通过 API 客户端编排远端读取，自己从不创建租约）。
4. 参数带默认值，因此 15 处 `new HttpClientFactory(new ProxySettingsService())` 的测试构造点无需改动。

## 被否决的替代方案

**保留 `ConfigureHttp2`，但把推送收敛到组合根的一处**：改动更小，但「推送」这个能力还在，第 2 条缺陷（启动期默认值窗口）也还在——那正是要消除的。

**偏好来源改为缓存快照（订阅编辑器变更事件）**：能省掉每次租约的一次 `GetSavedSnapshot()` 深拷贝，但引入一个必须与编辑器同步的缓存对象。代理闭包已经在每次请求读同一个快照，本项只是让 HTTP/2 读第二次；在实测显示成本之前不加这层机制。

**给工厂保留一个仅供测试的 setter**：等于把推送换个名字留下。测试改为构造带可变局部变量的闭包，顺带能表达「来源改变后新建租约跟随」这条本来无法表达的性质。

## 后果

- 调用方不再需要「记得推」：偏好随已保存设置变化，下一条租约自动跟随（`CreatedClients_WhenThePreferenceSourceChanges_TrackItWithoutAnyPush`）。
- 接线由容器级用例钉住：`SavedHttp2Setting_IsReadByLeasesCreatedAfterwards_WithoutAnyPush` 走真实 `AddLauncherServices`，保存设置后新建租约的 `DefaultRequestVersion` 跟随（变异注入把闭包写死 `true` 即变红；把偏好改成构造时读一次，前一条用例变红）。
- 启动期窗口不再由字段默认值决定：偏好来自播种后的编辑器快照（`ShellLifecycle.cs:230` 早于 `:242` 的 `LoadAsync`）。这条顺序依赖在本仓库已经存在——`CheckForStartupUpdateAsync` 读 `GetSavedSnapshot().UpdateChannel`，代理闭包读同一个快照——本次只是让 HTTP/2 加入它，未新增机制。
- 三条按推送命名的旧用例改写为租约级断言：断言的是用户实际拿到的协商版本，而不是「调过某个方法」。
- **接受一处残余风险（2026-09-15 复核补记）**：偏好来源是带默认值的构造器参数（缺省开启），而 .NET 容器对未注册的可选参数会回退到声明的默认值——若注册被改回 `AddSingleton<HttpClientFactory>()`，工厂会静默变成「HTTP/2 常开」，与本次要消除的「忘了推」属同一类失效。接受它的前提是仓库只有一处组合根，且 `SavedHttp2Setting_IsReadByLeasesCreatedAfterwards_WithoutAnyPush` 恰好走 `AddLauncherServices`：那把注册改动会让它变红。第 4 条决策（省掉 15 处测试构造点）换来的就是这条风险。
