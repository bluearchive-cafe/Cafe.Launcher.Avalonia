# ADR-071：主壳玻璃表面采用窗口内采样模糊（Fluid.Avalonia.Acrylic）

## 背景

主壳（壁纸首页）的玻璃表面当前是「半透明实底 token」：`Launcher.Color.Glass.*` 系列（亮/暗各四档）叠加在窗口内壁纸之上，没有真实背景模糊。设计规范同时记录了不用系统 Acrylic/Mica 的理由：壁纸层在窗口内部且始终铺满，原生窗口材质不可见。

2026-11-20 的材质调研与 spike 得出三条路线的边界：

1. **系统整窗材质**（`TransparencyLevelHint="Mica"/"AcrylicBlur"`）：采样桌面，与「壁纸在窗口内」的架构冲突，且整窗粒度不能服务单个表面。
2. **WinUIComposition 注入**（如 `CompositionMaterial.Avalonia`）：真 per-shape 原生材质，但采样窗口背后的桌面而非窗口内内容，且硬锁 Avalonia 12.1.4（项目为 12.1.6），直接不可用。
3. **Skia 窗口内采样**（`sample-and-blur`）：对窗口内已渲染内容做捕获 + 模糊，与「壁纸在窗口内」正配，且跨平台（Skia 渲染器）。

spike（`prototypes/GlassMaterialLab/`）同屏对照了三种实现与现行实底基线：

- A 内置 `ExperimentalAcrylicBorder`（`BackgroundSource=Digger`，零新增依赖，实验性）；
- B `Fluid.Avalonia.Acrylic` 1.4.0（节流捕获 + 参数缓存 + Skia shader）；
- C `JuffMa.Controls.Acrylic` 2.0.0（手动快照，静态缓存型）；
- D 现行实底 token。

验证结果（Windows 11 26100 / 1080p60）：完整配置 3×25s + 40s 浸泡稳定；四玻璃面同时活动 60 FPS（平均 16.6 ms、峰值 18.6 ms）；应用内自转储确认 A/B 均实时跟踪动态背景；软件渲染下功能可用但降至 8 FPS（平均 123 ms、峰值 378 ms）。维护者人工对比后选择 **B**：模糊观感与文字可读性最接近 Fluent 玻璃预期。

## 决策

1. **实现**。主壳窗口内的玻璃表面采用窗口内采样模糊，实现选用 **`Fluid.Avalonia.Acrylic` 的 `AcrylicSurface`**（MIT，Avalonia 12+，Skia 渲染器）。分析器与 `BlurRadius`、`Vibrancy`、`TintColor` 等参数以设计规范中的玻璃档位（标准/强档）为唯一来源，不在调用点散落魔法值。
2. **适用边界**。仅适用于**主窗口 TopLevel 内**的常驻玻璃表面（首批：顶部工具行背后的内容区、资讯面板、右下主操作、任务卡）。以下表面**保持实底 token**，不接入：
   - 菜单、工具提示等弹出层——它们是独立 `TopLevel`，沿窗口内采样管线取不到主窗口内容；同理不引入「弹窗内假玻璃」。
   - 对话框、设置整窗页、通知卡——ADR-070 已定为实心中性表面，本 ADR 不回退该决定。
   - 独立崩溃窗口——独立 Fluent 资源边界，见 ADR-020。
3. **回退是契约的一部分**。`Launcher.Color.Glass.*` 继续存在，并作为以下情形的确定性回退，视觉上必须完整成立：
   - 软件渲染（`Win32RenderingMode.Software` / 远程会话）——实测 8 FPS 不可接受，整体退回实底；
   - headless 测试宿主；
   - 高对比度 / 强制色彩模式；
   - 上游后端不可用（`AcrylicSurface` 无法采样时）。
   玻璃档位与实底档位共用同一套语义键（标准/强档/发丝描边），切换只改实现不改设计语言。
4. **视频壁纸（2026-11-20 已验证闭合，2026-11-21 修订为近实时替身）**。mpv 走原生 GL 承载面，不进 Skia 采样快照：spike 复现了「只有被排除层」时玻璃采到纯色（均值 0.050／标准差 0.000），而「原生表面之下再铺替身」时玻璃采到模糊纹理（0.575／0.045）。因此视频壁纸启用时，在原生表面**之下**保留替身：先显示该视频的封面/首帧，随后以约 250 ms 的间隔从视频帧采样更新（`VideoBackgroundControl.CaptureSurrogateFrameIfDue`，降采样到短边 ≤ 180 像素），玻璃表面采样替身；替身被视频画面完全遮挡，用户不可见，≤ 0.25 s 的延迟在重模糊下不可辨。证据与复现方法见 `prototypes/GlassMaterialLab`（`GLASSLAB_VIDEO_SIM`）。
5. **依赖治理**。包版本登记在 `Directory.Packages.props`（禁止 csproj 内写版本）；更新第三方依赖清单与许可证声明；该包为小体量单维护者项目（spike 时 5★），若上游失维按 MIT 考虑 fork 内化，不改变本决策的接口层（`AcrylicSurface` 语义）。
6. **性能与诊断**。启动时按需启用上游提供的组合器/Skia 调优（`UseAcrylicPerformanceDefaults()`），并在开发构建保留帧读数；玻璃表面数量是性能预算的一部分，Fluent「材质服务层级、不铺满」的边界优先于视觉堆叠。

## 后果

- **分阶段落地**（每阶段独立可回退，同一变更内同步受影响文档与黄金基线）：
  - **P0 基础**：登记依赖；封装一层玻璃表面控件/样式（含回退开关与实底降级）；headless 与软件渲染回退断言；验证 `verify.ps1`。
  - **P1 首批表面**：资讯面板、主操作、任务卡、工具行背后的内容区接入；明/暗 × 四语言 × 最小窗口走查；更新 `docs/design/design-system-spec.md` 主窗口条目与玻璃 token 章节。
  - **P2 视频壁纸**：完成 mpv 复验并按结果落地第 4 条规则；更新 `docs/cafe-launcher/` 与 `docs/en/cafe-launcher/`（cafe-docs）中涉及玻璃/壁纸的用户说明。
- **接受代价**：每个玻璃表面都有持续捕获成本（捕获节流 ~33ms + 参数缓存可压低）；软件渲染整体退回实底意味着「无 GPU 时没有玻璃」；引入一个实验期的小型第三方依赖。相对收益是主壳玻璃获得真实模糊与随壁纸变化的动态质感，这是实底 token 无法达到的。
- **被否选项**：内置 `ExperimentalAcrylicBorder`（实验控件、重绘行为不可控）；`JuffMa.Controls.Acrylic`（静态快照，动态背景下残影与逐帧重采代价二选一）；`CompositionMaterial.Avalonia`（采样桌面 + 版本硬锁）；自研 WinUI 注入（维护成本高于收益）。
- 研究证据与可复现方法保留在 [`prototypes/GlassMaterialLab/`](../../../prototypes/GlassMaterialLab/README.md)，不属于生产架构。
- 落地进度：P0（2026-11-20）与 **P1 首批表面（同日）完成**：左侧图标栏（Rail 档）、资讯整组与浮动任务卡（Strong 档）接入 `GlassSurface`，回退态与旧实底逐像素一致（黄金基线 51/51 通过）；能力接线为组合根显式开关 `GlassSurfaceSupport.Enabled`（宿主读取 `CAFE_DISABLE_GLASS=1`），软件渲染、远程会话与高对比按第 3 条手动降级；公开 API 没有可靠的软件渲染探测点，因此不做自动猜测。**P2 视频壁纸规则已闭合**（第 4 条）：生产侧在视频层之下保留**近实时替身**（`VideoPosterSurrogate`，约 4 Hz 从视频帧采样），供玻璃采样。
