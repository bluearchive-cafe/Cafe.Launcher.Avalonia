# ADR-025：数据根由组合根解析一次并注入

- 状态：✅ 已接受
- 日期：2026-09-15
- 来源：架构深化评审（第二轮 · 2026-09-14）候选 03
- 相关：ADR-019（不可恢复崩溃两级兜底）、ADR-023（模态注册声明式收敛）、ADR-024（已保存设置唯一写入方）

## 背景

「启动器私有数据放在哪」是一个进程级静态读（原 `LauncherUserDataDirectory.Root`：测试覆盖环境变量优先，否则本机 `LocalApplicationData` 下的产品目录）。`src/` 内 15 处生产消费点各自读它，其中八个模块（设置服务、图片缓存、日志导出、崩溃快照、下载检查点、公告已读状态、窗口 chrome/调试面板、日志器）为此各长出一段测试专用构造器：有的收文件路径、有的收目录、有的收「主目录 ＋ 回退目录」。测试要改落点，就得先认识这些不同形状的入口。

两处事实在落地前被复核更正，记在这里以免后人按卡片原文理解：

- 卡片把 `LocalDiagnostics` 也算作一条数据根阶梯，但它那个「测试专用构造器」指向的是 `Path.GetTempPath()` 而非数据根，与本题无关，未改动。
- 卡片称测试摩擦是「本域最集中的测试摩擦」，这一表述偏高：静态那条路本来就有单一覆盖点（`tests/TestUserDataIsolation.cs` 的模块初始化器设置 `CAFE_LAUNCHER_TEST_USER_DATA_DIRECTORY`）。真正的问题不是测试改不动落点，而是**每个模块都能各读一次进程级静态**——包括那些根本不该知道数据在哪的模块。

## 决策

1. 新增 `Services/LauncherDataRoot.cs`：数据根 ＋ 根内知名路径的唯一出处（`SettingsPath` / `DownloadStatePath` / `NoticeStatePath` / `UnifiedLogPath` / `ImageCacheDirectory` / `CrashReportsDirectory` / `LogExportDirectory`）。文件名仍由 `GamePaths` / `LauncherConstants` 声明，本模块只负责布局与组合。
2. 进程根只在少数几处解析：组合根（`ServiceConfiguration.AddLauncherServices`）解析一次并登记为单例；ADR-019 保护的 pre-DI 路径各解析一次（`Program.cs` 的首启探测/崩溃日志器/单实例信号、`CrashReportApp` 的独立崩溃进程、`UnifiedLogger` 的显式目录、`GameCompatibilityPaths` 在 Windows 上复用启动器数据根）。允许解析的文件由声明表守卫钉住。
3. 其余模块一律接收注入的 `LauncherDataRoot`，它们原先「自己解析默认根」的构造器与测试专用阶梯一并删除——测试改为构造一个临时目录上的数据根（`TestDataRoot`）。
4. 删除 `LauncherUserDataDirectory`：解析与布局合为一个模块，避免同一概念两个出处。
5. `UnifiedLogger` 不再接受 `null` 目录（原先 `null` 表示「解析进程根」）；`CrashReportWindow` 的数据根由调用方给出，设计期预览用临时目录。

## 被否决的替代方案

**只加 DI 工厂、不做注入**（组合根把路径算好传给各服务的现有路径构造器，静态读取离开服务但仍留在类型系统里）：改动更小、测试零改动，但「数据放哪」仍是一个任何模块都能读的进程级入口，守卫只能靠约定；下次新模块仍可能顺手直接读。取注入方案，代价是一次涉及面较广的机械改接（生产 15 处 ＋ 测试约 150 处构造点），换来的是**编译期约束**：拿不到数据根就写不出落点。

## 后果

- 新增模块要落盘时，构造器要求一个 `LauncherDataRoot`；忘记注入是编译错误，不是运行期读到真实用户数据目录。
- 测试换根只在一个接缝上发生：`TestDataRoot.ForDirectory/ForFile/ForCurrentProcess`。
- 布局知识集中到一处，`LauncherDataRootTests` 断言每个知名路径都是「根 ＋ 已声明的名字」。
- 静态入口收窄到 pre-DI 残余（ADR-019 的两级兜底不变），由 `TestUserDataIsolationTests.ProcessRootResolution_IsConfinedToDeclaredPreDiSites` 的表守卫。
- 既有 `PersistentUserDataPaths_UseCentralDirectoryProvider` 守卫继续拦「直接读 `Environment.SpecialFolder.LocalApplicationData`」的写法，两者互补。
