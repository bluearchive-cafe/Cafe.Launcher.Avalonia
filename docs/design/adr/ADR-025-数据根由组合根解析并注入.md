# ADR-025：数据根由组合根解析一次并注入

- 状态：✅ 已接受
- 日期：2026-09-15
- 相关：ADR-019（不可恢复崩溃两级兜底）、ADR-023（模态注册声明式收敛）、ADR-024（已保存设置唯一写入方）

## 背景

「启动器私有数据放在哪」原先是进程级静态读（`LauncherUserDataDirectory.Root`：测试覆盖环境变量优先，否则本机 `LocalApplicationData` 下的产品目录）。`src/` 内 15 处生产消费点各自读它，其中八个模块（设置服务、图片缓存、日志导出、崩溃快照、下载检查点、公告已读状态、窗口 chrome/调试面板、日志器）为此各长出一段测试专用构造器——有的收文件路径、有的收目录、有的收「主目录 ＋ 回退目录」。

测试换根本来就有单一覆盖点（`tests/TestUserDataIsolation.cs` 的模块初始化器设置 `CAFE_LAUNCHER_TEST_USER_DATA_DIRECTORY`），真正的问题不是测试改不动落点，而是**每个模块都能各读一次进程级静态**——包括那些根本不该知道数据在哪的模块。

## 决策

1. 新增 `Services/LauncherDataRoot.cs`：数据根 ＋ 根内知名路径的唯一出处（`SettingsPath` / `DownloadStatePath` / `NoticeStatePath` / `ImageCacheDirectory` / `CrashReportsDirectory` / `LogExportDirectory`）。文件名仍由 `GamePaths` / `LauncherConstants` 声明，本模块只负责布局与组合。
2. 进程根只在少数几处解析：组合根（`ServiceConfiguration.AddLauncherServices`）解析一次并登记为单例；ADR-019 保护的 pre-DI 路径各解析一次（`Program.cs` 的首启探测/崩溃日志器/单实例信号、`CrashReportApp` 的独立崩溃进程、`UnifiedLogger` 的显式目录）。允许解析的文件由声明表守卫钉住。
3. 其余模块一律接收注入的 `LauncherDataRoot`，原先「自己解析默认根」的构造器与测试专用阶梯一并删除——测试改为在临时目录上构造数据根（`TestDataRoot`）。
4. 删除 `LauncherUserDataDirectory`：解析与布局合为一个模块，避免同一概念两个出处。
5. `UnifiedLogger` 不再接受 `null` 目录（原先 `null` 表示「解析进程根」）；`CrashReportWindow` 的数据根由调用方给出，设计期预览用临时目录。

## 备选方案

- **只加 DI 工厂、不做注入**（组合根把路径算好传给各服务的现有路径构造器，静态读取离开服务但仍留在类型系统里）：改动更小、测试零改动，但「数据放哪」仍是任何模块都能读的进程级入口，守卫只能靠约定。取注入方案的代价是一次涉及面较广的机械改接（生产 15 处 ＋ 测试约 150 处构造点），换来的是**编译期约束**：拿不到数据根就写不出落点。

## 后果

- 新增模块要落盘时，构造器要求一个 `LauncherDataRoot`；忘记注入是编译错误，不是运行期读到真实用户数据目录。
- 测试换根只在一个接缝上发生：`TestDataRoot.ForDirectory/ForFile/ForCurrentProcess`。
- 布局知识集中到一处，`LauncherDataRootTests` 断言每个知名路径都是「根 ＋ 已声明的名字」。
- 静态入口收窄到 pre-DI 残余与声明表列出的例外，由 `TestUserDataIsolationTests.ProcessRootResolution_IsConfinedToDeclaredPreDiSites` 的表守卫；`PersistentUserDataPaths_UseCentralDirectoryProvider` 继续拦「直接读 `Environment.SpecialFolder.LocalApplicationData`」的写法，两者互补。
- 落地后更正：`UnifiedLogPath` 在生产里没有消费者（日志落点由 `UnifiedLogger` 实例拥有，构造时收目录、经 `LogFilePath` 读出），根上再声明一份等于给同一份布局留第二个出处——该属性与其测试行已删除；日志文件名仍由 `LauncherPaths.UnifiedLogFileName` 单点声明（S0 之前该类叫 `GamePaths`，其游戏专用成员已移入 `Models/YostarGameProfile`）。
- 落地后更正：`LogExportService` 曾仍自行拼根内路径（`Path.Combine(dataRoot.Root, 文件名)`），已改为消费 `SettingsPath` / `DownloadStatePath` / `NoticeStatePath`，导出条目名由 `Path.GetFileName` 从这些路径派生，压缩包内容不变。
- 落地后更正：`GameCompatibilityPaths` 不属于 ADR-019 的 pre-DI 路径，而是「已声明但没有 DI 接缝」的例外——静态助手，由 post-DI 的 `GameRuntime` 调用时解析 Windows 根（Unix 分支走 XDG 数据主目录）。该例外已由 [ADR-048](ADR-048-Linux按XDG基目录拆分数据根.md) 消除（改为接收注入 `LauncherDataRoot` 的实例类），声明表因此只剩 `LauncherDataRoot.cs`、组合根、`Program.cs` 与 `CrashReportApp.axaml.cs` 四处。ADR-048 的 XDG 四类根拆分随后由 [ADR-049](ADR-049-Linux保留单一数据根并统一小写目录名.md) 在发布前撤销；本 ADR 的决定（解析一次、注入消费、测试换根）与那次声明表缩减继续有效。
