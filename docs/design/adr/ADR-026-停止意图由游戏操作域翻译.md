# ADR-026：停止意图由游戏操作域翻译，域外不命名检查点决策

- 状态：✅ 已接受
- 日期：2026-09-15
- 来源：架构深化评审（第二轮 · 2026-09-14）候选 05
- 相关：ADR-021（保留操作后端接缝）、ADR-025（数据根注入）

## 背景

「停止下载是否保留续传」由 `DownloadStopReason` 表达（`UserRequested` 丢弃持久化检查点、`ApplicationExit` 保留）。它原先声明在共享的 `Models/LauncherEnums.cs`，于是任何模块都能替下载模块做这个决定。生产里真正选择该值的调用点有四处、分布三个模块：`WindowChromeViewModel`（关窗并停止 → `UserRequested`）、`GameOperationJourney.PerformStop`（用户确认后停止 → `UserRequested`）、`ShellLifecycle.PrepareForShutdownAsync` 与 `Dispose`（→ `ApplicationExit`）。

`WindowChromeViewModel` 因此必须持有具体的 `GameOperationsViewModel`：它只用到该类型的两个成员，其中 `IsDownloadRunning` 已在窄视图 `IGameOperationActivity` 上，唯一需要具体类型的就是带原因的 `StopDownload(reason)`——而窄视图上的 `StopOperation()` 语义是「用户按下停止 → 域弹确认框」，不是「立即停止」。

两处事实在落地前复核更正：

- 窄视图的存在理由**不是**窗口 chrome。它的文档写明服务诊断面板（`DebugViewModel` 只依赖本抽象，避免 Diagnostics 与 GameOperations 横向耦合），唯一消费者也是 `DebugViewModel`。窗口 chrome 切过去是本项的收益，不是该接口的由来。
- `LauncherEnums.cs` 的注释把「窗口销毁」归入 `ApplicationExit`（保留检查点），而关窗手势实际走 `UserRequested`（丢弃）——**注释与行为矛盾**，且该行为被 `WindowChromeViewModelTests.CloseAfterStoppingDownload_ClearsPersistedStateAndClosesWindow` 与共用的关闭确认文案钉住。所以这不是用户可见故障，是口径错。

## 决策

1. 新增意图词表 `Services/GameOperationStopIntent.cs`（`UserStop` / `ProcessExit`），与窄视图同处共享层。域外的调用方只表达「为什么停」。
2. `DownloadStopReason` 移入 `Features/GameOperations/`：检查点去留是域内策略，域外不再命名它。
3. 翻译发生一次：`GameOperationsViewModel.StopOperation(intent)` 经 `ToStopReason` 映射到原因；`WindowChromeViewModel` 与 `ShellLifecycle` 改为传意图。
4. `IGameOperationActivity` 的停止入口按语义拆开：`RequestStop()`（用户手势，域决定是否先确认）与 `StopOperation(GameOperationStopIntent)`（立即停止）。前者由原来的无参 `StopOperation()` 更名而来——原名字同时承担两种语义，正是这条接口过去无法被 chrome 使用的原因。
5. `WindowChromeViewModel` 的 `operations` 字段类型由具体展示 VM 收窄为 `IGameOperationActivity`。
6. `DownloadStopReason` 的注释修正：关窗并停止属于 `UserRequested`，`ApplicationExit` 仅指「进程退出且会话未被用户显式停止」。行为不变。

## 被否决的替代方案

**只修注释、保留原因级入口**：改动最小，但「任何模块都能命名检查点决策」的能力原样保留，窗口 chrome 也仍然需要具体展示 VM。取意图词表方案，代价是一次跨三个模块的机械改接与一次命令更名（`StopOperationCommand` → `RequestStopCommand`，连带视图绑定与样式契约表）。

**在窄视图上加重载 `StopOperation(reason)`**：接口上会同时存在「打开确认框」与「立即停止」两种语义的同名成员，正是本项要消除的混淆，否决。

## 后果

- 新增停止入口时只可能表达意图；域外拿不到检查点决策（`GameOperationStopOwnershipTests.DownloadStopReason_IsNamedOnlyInsideTheGameOperationsFeature` 以内容扫描守卫，变异注入已验证会咬并报出文件名）。
- 窄视图的形状被钉住：`IGameOperationActivity_ExposesIntents_NotTheCheckpointDecision` 断言两个入口存在、且接口上不出现以检查点决策为参数的成员（变异注入已验证会咬）。
- 意图到原因的映射是两套词表唯一的接触点，位于域 VM；行为由 `GameOperationsViewModelTests` 的两条映射用例钉住。
- 接口成员不能命名为 `Stop`（CA1716：VB 保留字），故立即停止入口命名为 `StopOperation`。
- 域内仍然保留 `PerformStop()`（确认流程的完成动作）与 `journey.Stop(reason)`（域内传递）。
