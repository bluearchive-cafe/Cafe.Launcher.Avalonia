# ADR-027：策略只给判定结果，确认之后的拒绝必须有可见反馈

- 状态：✅ 已接受
- 日期：2026-09-15
- 来源：架构深化评审（第二轮 · 2026-09-14）候选 10
- 相关：ADR-021（保留操作后端接缝）、ADR-026（停止意图由域翻译）

## 背景

`GameOperationPolicy.Allows(operation, state)` 返回布尔，8 个生产调用点各自解释这个布尔，实测共 4 种反应：

| 反应 | 调用点 | 说明 |
| --- | --- | --- |
| 类型化失败 ＋ **按状态定制**的文案 | `GameLaunchService` | 启动的拒绝原因就是具体状态（损坏／IO 失败／远端不可用），文案因此不同 |
| 类型化失败 ＋「当前状态不可用」 | `GameDownloadService` ×2、`GameUninstallService` | 执行边界 |
| 警告 Toast ＋ 中止 | `GameOperationsViewModel` 的 RequestRepair / RequestUninstall | 表示层预检 |
| **静默什么都不做** | `GameOperationJourney.ConfirmUninstallAsync`、`GameOperationsViewModel.RepairAsync` | 用户已经在确认框上点过确认之后 |

前三种是合理的分层渲染（策略回答「允不允许」，配哪句话由调用层定，这条职责划分本身没问题）。第四种是缺陷：确认框打开期间后台刷新可能把状态改掉（例如从 Ready 变成 UpdateAvailable／Corrupted），用户点了确认却什么也不会发生——没有提示、没有结果、面板回到原样。

卡片只点名了 journey 的那一处；落地前复核发现 `GameOperationsViewModel.RepairAsync` 是**同一类的第二处**，而且它当时是被测试半钉住的：`RequestRepairAndRepair_WhenStateIsInvalid_DoNotCallBackend` 断言「不调用后端、不开确认框」，等于把静默写进了契约。卡片点名的那一处也有这类契约，但它钉的是 journey 的路径（`GameOperationJourneyTests.ConfirmUninstallAsync_WhenNotReady_SkipsUninstall`，本轮改名为 `…_ReportsInsteadOfSilence`），不是 VM 的修复路径——两者不是同一条用例（2026-09-15 复核时更正此处引用）。

## 决策

1. 策略不再对外给布尔：`GameOperationPolicy.Decide(operation, state)` 返回 `GameOperationDecision`（`Allowed` / `RejectedForCurrentState`）。判定表仍是唯一真相，但降为私有实现细节。
2. 调用方必须对「被拒绝」这一支表态——「拒绝之后什么都不做」只能是有意写出来的，而不是漏掉 else。
3. 两处静默窗口关闭：
   - `GameOperationsViewModel.RepairAsync`（确认后的修复）改为渲染与预检相同的警告 Toast。
   - `GameOperationJourney.ConfirmUninstallAsync`（确认后的卸载）改为渲染同样的警告 Toast（与它自己的 `PerformStop` 先例一致）。
4. 文案单点：两处复用预检已有的 `OperationUnavailableForCurrentState`，并在各自的类内收成一个私有方法，避免第三次手抄同一行。

## 被否决的替代方案

**只修那两处静默、保留布尔**：改动更小，但「拒绝被谁忽略」仍然要靠评审纪律；`Decide` 让第 9 个调用点必须显式处理拒绝。

**让策略直接产出文案**：会把本地化职责拉进策略表，且启动路径的按状态文案（损坏／IO 失败／远端不可用）是调用层知识。策略答「允不允许」，文案留在调用层——这条边界保持不动。

**让 journey 返回结果由 VM 渲染**：需要改 `IGameOperationJourney` 签名，而本仓库已有「journey 结果被调用方忽略」的先例（`executor.UninstallAsync` 的返回值即无人消费），把一个结果交给可能再次被忽略的路径，不如让拒绝在原地可见。

## 后果

- 确认之后的拒绝不再可能静默：`RepairAsync` 与 `ConfirmUninstallAsync` 各有行为用例（`…_ReportsInsteadOfSilence`），变异注入回退为静默时二者变红。
- 策略的形状被钉住：`Decide_IsTheOnlyPublicVerdict_NoBareBoolean` 断言公开面上没有返回布尔的成员（重新暴露一个即变红）。
- 全表测试（4 操作 × 7 状态）改为断言判定结果，枚举长度守卫不变。
- 启动路径的按状态文案、下载／卸载的执行边界失败结果、两个预检 Toast 均按原样保留。
