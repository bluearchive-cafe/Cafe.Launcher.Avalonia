# ADR-061: 设置向导新增欢迎首步与配置概览

- 状态：已接受（2026-11-12）

首次向导在 [ADR-059](ADR-059-设置向导统一舞台与双栏解剖.md) 统一解剖后仍直接落在语言选择：用户打开向导即面对一个具体字段，缺少「接下来会发生什么」的整体预期；跳过按钮又在同意前不可用，首屏因此既无引导也无退路说明。本次在流程最前新增欢迎页，保持 ADR-059 的双栏舞台不变，只增加一个步骤面板并把后续步骤整体顺延。

## 决策

- **步骤总数 7**：欢迎（0）→ 语言（1）→ 协议（2）→ 游戏路径（3）→ 下载源（4）→ 代理（5）→ 复核（6）。`SetupWizardViewModel` 的 `StepCount`=7，`AgreementStep`=2、`GamePathStep`=3、`ReviewStep`=6；复核摘要的「修改」入口指向 1／4／3／5。协议更新模式仍为单步，直接落在协议步（`Step = AgreementStep`），进度轨折叠并计数「第 1 步，共 1 步」。
- **欢迎页左引导**：56 圆形语义徽章取 `HandWave`（主色前景 + `Primary.Soft` 底），标题与说明复用 `setupWizardWelcomeTitle`／`setupWizardWelcomeText`，与其他步骤同构。
- **欢迎页右面板：只读配置概览**：Card 表面内是 caption（`setupWizardWelcomePlan`）加五行紧凑清单，顺序与后续步骤一致——语言、协议、游戏路径、下载源、代理。每行为「图标块 + 名称 + 一句话说明」，图标依次为 `Translate`、`ScriptText`、`FolderSearch`、`CloudDownload`、`SwapHorizontal`，名称复用各步骤标题键，说明取 `setupWizardWelcome*Description`（语言行复用既有 `setupWizardLanguageHint`）。行间以 `wizard-divider` 发丝线分界，首行之前不画线。
- **清单不可交互**：欢迎页只建立预期，不承担跳转；行内不设按钮或单选，避免首屏出现两套导航语义。用户按「下一步」进入语言步后才开始修改配置。
- **图标块静色**：清单图标块取 `Content.Row` 静底而非主色，让右面板保持「预览」语气，不与左栏欢迎徽章争夺焦点。
- **令牌**：新增 `Wizard.Welcome.Row.MinHeight`=42 与 `Wizard.Welcome.Icon.Size`=34，样式集中在 `Styles/SetupWizard.axaml` 的 `wizard-welcome-row`／`wizard-welcome-icon`／`wizard-welcome-name`／`wizard-welcome-desc`，视图不内联度量。
- **本地化**：新增 `setupWizardWelcomeTitle`、`setupWizardWelcomePlan`、`setupWizardWelcomeAgreementDescription`、`setupWizardWelcomeGamePathDescription`、`setupWizardWelcomeDownloadSourceDescription`、`setupWizardWelcomeProxyDescription`，四语齐全并由 `Generate-LocalizationCatalog.ps1` 校验。

## 未采用

- **欢迎页作为非步骤的浮层/首屏**：与 ADR-059 的单容器换面机制脱节，需要第二套显隐与动效编排；做成第 0 步即可复用同一换页、计数与动作带语义。
- **右面板放跳转入口**：首屏出现可点击行会与「下一步」形成两套导航，且未读协议时跳转目标多数被门禁挡住；概览保持只读。
- **复用复核页摘要行样式（`wizard-summary-row`）**：复核行是「标签/值 + 修改钮」的两行密集信息，欢迎行是名称/说明且更矮；复用会把两种语义压进同一组 token，后续任一侧调整都会互相牵制。

## 后果

- `SetupWizardOverlay.axaml` 新增 `WizardStep0`，原六步面板与进度轨整体顺延为 `WizardStep1..6`／`ProgressSegment0..6`；`SetupWizardOverlay.axaml.cs` 的面板与进度段数组扩为 7 项。协议步、下载源步、代理步、复核步的名字随之变化。
- 步骤断言与导航计数全面顺延：视图模型测试、样式契约测试、无头测试与 `setup-wizard` golden（现在截取欢迎页）同步更新；协议两张 golden 的导航多一“下一步”。
- 后续新增步骤必须同时更新欢迎页清单与步骤索引，保持「概览 = 后续配置」的一致性。
