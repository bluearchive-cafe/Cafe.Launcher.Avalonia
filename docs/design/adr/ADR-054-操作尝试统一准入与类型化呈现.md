# ADR-054：操作尝试统一准入与类型化呈现

- 状态：✅ 已接受
- 日期：2026-11-04
- 相关：ADR-021、ADR-027、ADR-029、ADR-032

VM、旅程和管线原先为同一次执行重复询问状态门；只复用允许集没有消除重复准入，展示层还负责确认、测量与执行衔接。现在由 `GameOperationAttempt.Evaluate` 唯一调用策略，允许时产生与操作种类绑定的尝试对象；执行器及管线接受该对象，不再次判定状态。独立管线入口也通过同一个准入模块适配，拒绝仍是类型化结果。

请求确认与确认后执行是不同阶段，不能把数分钟前的准入当作执行许可；确认和 Toast 重试重新建立尝试。每条失败 Toast 固定自己的原始安装目标；重试读取宿主最新快照，目标变化或快照缺失时拒绝，不把旧 Toast 转向新目录；同一目标使用最新状态与设置准入。此收敛只针对安装状态门，不删除路径、元数据、删除范围和游戏进程的 I/O 边界复查。保留 ADR-021 的执行器及可脚本化替身。

`GameOperationJourney` 拥有预检、确认、尺寸测量和执行衔接，通过 `GameOperationPresentation` 传递展示事实；宿主只保留只读状态、消息入口、刷新和日志入口。卸载尺寸消息携带请求版本，展示层将它绑定到自身确认页版本，迟到结果不能覆盖新页面。拒绝与预检失败继续按 ADR-027/029 可见，卸载完成结果继续留在原表面。

没有把确认前的结果永久缓存成通行证，也没有让执行器直接读取展示层状态：前者会放行过期状态，后者会把准入重复重新带回下层。
