# ADR-023: 模态栈注册收敛为声明式注册记录（修订 ADR-015 的显示管线冻结条款）

- 状态：**已接受**（2026-09-13，架构评审候选 06 落地前置修订）
- 背景：
  - ADR-015 冻结了「bool 属性 → `SyncModal` → ModalHost 栈」的显示管线（"显示管线不动"）。其原意是**显示语义**不在 v2 迁移中变动——模态栈的开/关行为、ESC 路由结果、对话框层无闸口裁定都保持现状。
  - 该管线在 `ShellLifecycle` 里的实现形态已退化为四张按种类展开的命令式表：17 处 `PropertyChanged` 订阅（含 8 个确认实例）、约 10 个 watcher 处理器方法（含 8 臂 `MapConfirmationModal` 映射）、19 臂 `TryHandleEscape` switch、`ModalHostViewModel` 的 8 个 `Is*Interactive` 闸口属性 + 11 行变更通知。
  - 逐臂核对确认：19 条 ESC 臂全部是**纯命令执行**（CloseCommand/CancelCommand/ShowCommand），零特例逻辑；每个模态的知识（种类 ↔ 可见性旗标 ↔ 取消命令 ↔ 栈内容）被拆散在 4-6 个相距很远的编辑点上。`TryHandleEscape_ForEveryModalKind_IsRoutedToThatModal` 理论测试已逐种类护航可见性入栈与 ESC 路由（含 `OpenModalAsync` 助手对未登记种类的 `default: throw`）。
- 决策（对 ADR-015「显示管线不动」条款的修订）：
  - **管线内部形态改为声明式**：每个模态一条注册记录（`ModalKind` + 可见性来源 + 可见性属性名 + 内容 + ESC 命令），由 Shell 内部通用 `ModalRegistrar` 统一订阅可见性并驱动 `ModalHost.Open/Close`、按栈顶查表分发 ESC。`ShellLifecycle` 的 watcher 处理器方法、种类 switch、`MapConfirmationModal` 全部删除。
  - **显示语义逐字不变**：仅在可见性属性自身变更时同步（按属性名过滤，非旗标变更不得引发重新入栈——防止下层模态被误拉到栈顶）；`Open` 的「关后重开=置顶」语义、ESC 分发到栈顶、未注册种类返回 false 的兜底全部保留；对话框层无闸口裁定（AGENTS.md 模态隔离条款）原样保留。
  - **注册完备性成为契约**：每个 `ModalKind` 恰有一条注册，由测试钉住；表格漂移从代码评审问题变为测试失败。
  - `ModalHostViewModel` 栈机制、`Is*Interactive` 闸口、AXAML 绑定不改动；ADR-015 留下的「DataTemplate 化留作将来独立议题」维持原状。
- 后果：
  - 新增一个模态的编辑点从 6 个（枚举、旗标、watcher、ESC 臂、闸口属性、AXAML）降到约 4 个（枚举、注册记录、闸口属性仅限七主叠层、AXAML）；确认家族经同构类型循环注册，一步到位。
  - `ShellLifecycle` 预计净减约 200 行；模态概念的家从 shell 管线代码移到数据记录 + 一个通用 Registrar。
  - 风险与护栏：注册顺序需保持原 Wire 顺序（多处旗标同时翻转时栈序依赖注册序）；现有 per-kind 理论测试与 headless 套件原样护航，不重制黄金基线。
  - 本修订只重写管线接线，不推翻 ADR-015 的任何视觉/解剖/动效决策；ADR-015 其余条款继续有效。
