# ADR-029：卸载预检失败必须给可见反馈，原因在执行层给出

- 状态：✅ 已接受
- 日期：2026-09-15
- 来源：架构评审复核（2026-09-15 工作树复核轮）
- 相关：ADR-027（策略判定结果与确认后拒绝反馈）

## 背景

ADR-027 关闭了「用户点过确认之后、策略又拒绝」的静默窗口。复核该轮落地时发现同一类缺陷还留在**确认之前**的一道闸上：

`GameOperationsViewModel.RequestUninstallAsync` 先过策略预检（有警告 Toast），再调 `journey.ValidateUninstallAsync`，而后者把执行层的失败结果压成 `null`：

```csharp
var validation = await executor.ValidateUninstallAsync(snapshot.LocalGame.GamePath);
return validation.Success ? validation : null;   // 失败原因在这里被丢掉
```

VM 拿到 `null` 后直接 `return`。于是「策略允许卸载、但执行层校验不通过」时，用户点卸载得不到任何反应——没有确认框、没有提示、面板原样。被丢掉的正是执行层已经准备好的本地化原因：`GameUninstallService.ValidateAsync` 的路径缺失、路径受保护、目录名非法、清单元数据缺失（`GameUninstallService.cs:138-160`）。

触发条件真实但不算日常：游戏目录被删／被移动、设置里把路径指到受保护目录、`game-launcher-config.json` 元数据不完整。与 ADR-027 记录的窗口类似——状态在用户看到按钮之后变了。

既有用例 `RequestUninstallCommand_WhenValidationFails_DoesNotShowConfirmation` 只断言「确认框不开」，等于把静默写进了契约。

## 决策

1. 预检失败**就地报出**：`GameOperationJourney.ValidateUninstallAsync` 在返回 `null` 之前渲染警告 Toast，返回 `null` 的语义收敛为「不可卸载，且原因已经说过」。
2. 文案用执行层给出的具体原因（`validation.Message`），而不是笼统的 `OperationUnavailableForCurrentState`——预检失败的原因是可执行的（去把目录放回来、改掉路径），笼统文案会让用户不知道下一步做什么。执行层没给原因时才退回 `ShowOperationUnavailable()` 复用那一条既有文案，避免弹出一个没有内容的提示。
3. 成功路径不得多报：只有失败才渲染。
4. `GameOperationJourney.ValidateUninstallAsync` 的签名不变（仍是 `Task<GameOperationResult?>`），但契约写进 XML doc：返回 `null` 表示失败**且已报**，调用方不得把它当成「无事发生」。

## 被否决的替代方案

**改签名把失败结果交回 VM 渲染**（`Task<GameOperationResult>`，VM 判 `Success`）：会让文案职责回到表示层，但 ADR-027 已经否决过同形状的方案——「把一个结果交给可能再次被忽略的路径，不如让拒绝在原地可见」，而本仓库确有 `executor.UninstallAsync` 返回值无人消费的先例。预检的调用点是用户手势、不是后台循环，就地报不会误报给被动检查（`ValidateUninstallAsync` 全树只有一个调用点）。

**保留 `null` 折叠但什么都不报**：就是当前缺陷本身。

**报笼统文案（复用 `ShowOperationUnavailable`）**：改动最小，但把「路径受保护」这类可执行原因降级成「当前状态不可用」，用户依然不知道怎么办。

**不修，记为 accepted-risk**：不成立。它与 ADR-027 已关闭的两处同类：都是用户手势之后什么都不发生。

## 后果

- 卸载预检失败不再静默：`ValidateUninstallAsync_WhenValidationFails_ReportsTheExecutorReason`（原因被报出、返回 null）与 VM 侧的 `RequestUninstallCommand_WhenValidationFails_ReportsReasonAndSkipsConfirmation` 各钉住一半；回退为静默即变红。
- 反向守卫：`ValidateUninstallAsync_WhenValidationSucceeds_ReturnsTheResultWithoutReporting` 钉住成功路径不产生 Toast。
- 无原因边界有直接断言：`RequestUninstallCommand_WhenValidationFailsWithoutReason_ReportsGenericWarning`。
- 文案单点保持：通用回退仍走 `ShowOperationUnavailable`，新增的具体原因来自执行层，两边都没有第二份手抄文案。
- ADR-027 的边界不变：它管的是**策略**判定；本项管的是**执行层校验**。两者都不允许「用户手势之后什么都不发生」。
