# ADR-016: M3 视觉之上的 Fluent 动效层

- 状态：**已接受**（2026-08-27，Fluent 动效重设计 grilling 会话）
- 背景：项目已经以 M3 语义完成色彩、形状、组件与表面设计，但既有动效仍以 `50/167/200/250ms`、指数缓动和通用“淡入 + 位移”组合为主；对话框还存在外壳与内部内容重复移动。用户希望按照 Windows Fluent 重新设计全项目动效，同时保留已经落地的 M3 视觉成果。
- 决策：
  - **分层不换肤**：保留 M3 色彩、形状、组件与布局语义；新增覆盖全项目的 Fluent 动效层，采用 Windows 的 Connected、Consistent、Responsive 原则并映射为 Avalonia 资源，不宣称 WinUI 像素级一致。
  - **统一动效家族**：正式语言为即时反馈、内容切换、空间连续、临时表面与重要完成。普通控件不缩放、不弹跳；设置同级分类交叉淡化；向导与手动轮播按前后方向短距离移动；自动轮播交叉淡化；对话框仅移动表面一次，内部内容不重复移动；Toast 从右侧进入并保持堆栈连续。
  - **时长与曲线**：语义时长收敛为 83ms（即时）、167ms（快速）、250ms（标准），仅较大的连续空间变化允许 333ms；使用 Windows 进入减速、退出加速和点到点曲线，取代现有指数缓动与含义重叠的 200ms Content 档。
  - **产品状态**：主窗口内容首次显示时整体快速淡入；游戏操作表面保持底边锚定，在安装、控制和进度状态间连续转换。安装、更新、修复、卸载和首次设置向导成功属于重要完成；停止和失败保留可恢复上下文，但不使用完成强调。错误和警告不震动。
  - **外观与窗口**：壁纸加载完成后交叉淡化，主题 Token 同步切换且不逐项插值；窗口缩放、最大化、还原与关闭不添加应用内部布局动画。
  - **动效偏好**：`完整动效` 始终启用并允许覆盖 Windows 已关闭动画的设置；`系统动效` 跟随 Windows；`降动效` 停用空间移动、自动轮播与大面积淡化，只有临时表面可保留最多 83ms 的纯透明度过渡。这是产品有意保留的用户自主权偏差。
  - **交互正确性优先**：高频变化以最新状态为准，不排队播放；模态退出完成后才把交互权与焦点归还下层；无法稳定流畅或正确中断的容器转换依次降级为快速交叉淡化、立即切换。
  - **验证与演进**：先在独立 Avalonia 动效实验台中比较现有、Fluent 与降动效三种模式；用户确认代表场景矩阵后再规格化、拆票并分批迁移。正式 Debug 设计画廊保留轻量可重播动效矩阵，自动化契约、Headless 状态/取消测试和实际 Avalonia 人工走查共同验收。
- 取代关系：本 ADR 取代 `docs/design/design-system-spec.md` §3.7 的既有动效数值与系统降动效搁置项，并取代 ADR-015 中与对话框 200ms 指数缓动、内部内容重复运动相冲突的表述；ADR-015 的 DialogSurface 结构、无缩放原则和模态栈方向保持有效。
- 后果：生产实现前必须先完成并确认独立 Avalonia 原型；现有 `Launcher.Motion.*`、`MotionTokens`、`MotionVisibility`、页面切换、Toast 堆栈和相关测试需要按后续规格分批迁移。配置键和 `MotionModes` 值保持兼容。
