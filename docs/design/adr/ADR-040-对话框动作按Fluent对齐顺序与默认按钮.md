# ADR-040: 对话框动作按 Fluent 对齐 —— 顺序翻转、默认按钮、标准动作底色

- 状态：**已接受**（2026-09-25，用户指示「翻转动作顺序、设置默认按钮、更改动作按钮的背景色」并直接在项目中实现；同日两条修订并入决策 4、5），并**取代** ADR-015 中「取消/次要操作在左，确认/危险确认在右」与「安全钮在左、主钮填充在右」的顺序表述，以及 ADR-014 中同义的那一句。ADR-015 的其余条款（统一外壳、Basic/Panel 两形态、动效通道、尺寸律、关闭矩阵）不变。
- 日期：2026-09-25
- 相关：`Controls/ConfirmDialog.axaml`、`Controls/ConfirmDialog.axaml.cs`、`Views/MainWindowDialogsOverlay.axaml`（更新对话框）、`Views/MainWindowLogExportOverlay.axaml`、`Views/MainWindow.Styles.axaml`、`Views/OverlayFocusBehavior.cs`、[MS Learn · Dialog controls](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/dialogs-and-flyouts/dialogs)

## 背景

改动前是 M3 语义：动作顺序「取消在左、确认在右」，默认焦点落在安全操作，动作为「透明描边的次要按钮 + 填充的主要按钮」（ADR-014 / ADR-015）。目标平台的规则正好相反——WinUI `ContentDialog` 的 **PrimaryButton（do-it）在最左、CloseButton（安全动作）在最右**；`DefaultButton` 获得 Accent 外观、响应 Enter、打开时取得初始焦点；Esc / 系统返回 / 手柄 B 等价于 CloseButton；每个对话框至少有一个安全动作；焦点所在控件若自行处理 Enter，默认按钮不响应。Fluent 基础规范（`.agents/skills/designing-fluent-interfaces/references/foundations.md`）另要求标准控件有静止填充（`ControlFillColorDefault`）而非透明描边、控件圆角 4 / 浮层圆角 8、焦点使用显式焦点描边。顺序与默认动作语义都与目标平台相反，这是本轮改动的直接动因。

## 决策

1. **动作顺序翻转**（do-it 在左、安全动作在右）：`Controls/ConfirmDialog.axaml`、`Views/MainWindowDialogsOverlay.axaml`（更新对话框）、`Views/MainWindowLogExportOverlay.axaml`。通用不变量「`StackPanel.confirm-actions` 里 do-it 动作必须出现在 flat-action 之前」由契约测试守护，后续新增动作自动受约束。
2. **默认按钮**：非破坏性确认 → 确认动作即默认按钮（`primary-action` 的强调填充就是 Fluent 的 Accent 外观；Enter 由 `ConfirmDialog` 的冒泡 `KeyDown` 承接，已被焦点控件处理的 Enter 不会到达；打开时初始焦点落在确认按钮）。破坏性确认（`IsDangerConfirm`）→ **不设默认按钮**，初始焦点仍在安全动作，Enter 因此落在安全动作（保留仓内「默认焦点落在安全操作」的不变量）。**明确不使用 `Button.IsDefault`**：主窗口同时存在多个 `ConfirmDialog` 实例（`IsOpen` 互斥），而 `IsDefault` 是窗口级候选，隐藏实例之间的归属无法在本地约束；改由对话框自己判定 Enter 落点，`DefaultActionCommand` 是唯一判定处，行为测试与实现共用。
3. **动作按钮底色**：新增中性 token `Launcher.Color.Dialog.Action.Background`（Light `#FFF4F8FC` / Dark `#FF222B38`）。动作带里的标准（次要）动作从「透明描边」改为**静止填充**（Fluent 标准按钮语言）；强调/危险动作保持纯填充，并把家族基类新增的 1px 描边置空（否则填充按钮会被描一圈灰边）；禁用态改用 `Content.Row`。作用域限定 `StackPanel.confirm-actions`，设置区、内容区里同样使用 `flat-action` 的按钮不受影响。该 token 是中性层色，登记进 `MaterialSchemeGenerator.NeutralContentDefaults`，**不跟随种子**（ADR-010）——动作底色的语义是「中性控件填充」，不是品牌色。
4. **动作按钮无可见边框，但常驻预留焦点环厚度**（同日修订：先按「去除对话框按钮边框」去边，再由用户报告「按钮在有焦点环和没有的宽度是有区别的」补上预留）：`Button.confirm-dialog-action` 的 `BorderThickness` 由 1 改为 `None`、`BorderBrush` 透明，动作带里的次要动作同样处理，形状完全由底色（中性填充 / Accent / critical）表达。新增作用域规则 `StackPanel.confirm-actions Button`：`BorderBrush` 透明 + `BorderThickness = Launcher.Border.Thickness.Focus`（2）；它同时承担「无可见边框」与「预留厚度」，覆盖全部四种动作（确认 / 危险 / 次要 / 主钮），包括不属于 `confirm-dialog-action` 家族的更新 / 日志导出 / 错误对话框按钮。`StackPanel.confirm-actions Button:focus-visible` 只设 `BorderBrush`（FocusRing），**不再设厚度**；家族规则里的 `BorderBrush` / `BorderThickness` 声明随之删除，避免两处各写一遍。关闭钮 `.dialog-close` 不需要处理（固定 `Width` / `Height`，聚焦时厚度 0→1 只挤压内容区）。根因是焦点环用 `BorderThickness` 画而按钮宽度内容驱动：静止 0px、聚焦 2px 时聚焦那一刻变宽 2～4px、右对齐的动作带整体左移（落差因静止厚度 1px→0px 从 2px 变成 4px）。
5. **焦点视觉只在键盘导航时出现**：框架默认焦点矩形（`FocusAdorner`）在 `Views/MainWindow.Styles.axaml` 末尾全局置 `null`——它不是本仓语言，且会与应用自己的 FocusRing 叠成双层框；焦点环本身保留在各控件既有的 `:focus-visible` 规则上（Button / ComboBox / ToggleSwitch / ListBoxItem / RadioButton / 关闭钮 …），**不删不改**。程序式聚焦改用 `NavigationMethod.Unspecified`（不再是 `NavigationMethod.Tab`）：`Views/OverlayFocusBehavior.cs`（打开叠层的自动聚焦 + 关闭时归还焦点）与 `Controls/ConfirmDialog.axaml.cs`（打开确认框时的初始焦点），于是打开瞬间不画环、鼠标点击也不画，只有真按 Tab / 方向键时 Avalonia 才置上 `:focus-visible`；可达性满足 WCAG 2.4.7。动作带按钮无边框，而家族的无边框规则声明在 `Button:focus-visible` 之后、会盖掉它，因此额外补一条 `StackPanel.confirm-actions Button:focus-visible` 把 FocusRing 显式写回来——**该条不是冗余**：删掉它，键盘导航时 `BorderBrush` 退回全透明、`BorderThickness` 0，焦点不可见（Avalonia 按声明顺序取最后一个匹配的 Setter）。

## 后果

- 守卫：`UiStyleContractTests.Dialogs`（do-it 先于安全动作、确认框按钮命名顺序、底色/描边契约）；`ConfirmDialogHeadlessTests`（顺序、默认按钮落点、Enter 只触发一次、破坏性确认忽略 Enter）；`DialogActionButtonContractTests` 的类名与计数未变。焦点视觉由 `UiStyleContractTests.FocusVisual_IsKeyboardOnly` 守护（框架矩形为空 + FocusRing 仍在 + 动作带补回规则声明在无边框规则之后 + 预留厚度规则声明在静止样式之后、颜色规则在预留之后 + 聚焦规则不得再动 `BorderThickness` + 源码中不得出现 `Focus(NavigationMethod.Tab)`），`UiStyleContractTests.Dialogs` 里 `OverlayFocusBehavior` 的源码契约断言 `Unspecified`；行为测试 `DialogActionButtons_ShowFocusRingOnlyOnKeyboardNavigation`、`FocusVisual_FollowsKeyboardNavigationOnly`、`DialogActionButtons_KeepGeometryWhenTheFocusRingAppears`（键盘取焦前后逐个按钮的 `Bounds` 宽度 / 横坐标 / 高度必须完全相等）、`DialogActionButtons_ShowNoVisibleBorderAndReserveTheFocusRing`（描边 alpha 0 + 厚度 2）。
- 黄金基线：`Baselines/confirm-dialog.png` 与 `Baselines/log-export.png` 重制。首轮换位的实测变更量为 **0.55% 像素**、包围盒 `x 745..891 / y 393..434`（只有动作带内两个按钮换位），窗口其余部分逐像素未动——这解释了 1% 容差的比较在重制前仍会「偶然绿」；最终 `confirm-dialog.png` 1586 px（0.16%，`x 742..891 / y 393..434`）、`log-export.png` 620 px（0.06%，动作带底行），`settings-overlay` / `shell-default` / `progress-panel` 未变。
- 重制基线的操作注意：`.\test.ps1 -UpdateGolden` 会重写**全部**基线，而 toast 的渲染在容差内并非位确定（三轮修订中 `toast.png` 各出现一次同容差无意图漂移，均已 `git` 复原）。重制后必须核对 `git status`，只保留有意图变化的那几张。
- 已知代价与未覆盖：静止态每个动作按钮因此宽 2～4px（宽带按钮按内容增长，窄按钮被 `MinWidth` 吸收）——这是「聚焦不跳」的必要成本，若要连这 2～4px 都不动，正确做法是改用 Avalonia 的 `FocusAdorner`（叠加层绘制、不参与布局）而非描边，但那需要自定义 adorner 模板并做视觉目检，本轮未做。**设置工作区**（z=100 的常驻表面）的「取消 / 保存」顺序**未翻转**（它是常驻工作区而不是瞬态对话框，属另一个决策）；动作带**之外**的按钮（设置区页脚、工具栏等）仍是静止 1px / 聚焦 2px 的落差，这是改动之前就有的行为。FluentTheme 在少数控件**模板内部**绘制的焦点反馈（TextBox 底线、CheckBox/ToggleSwitch 模板边框等）本来就只在键盘导航时出现，无需处理。
- 明确记录的两处 Fluent 偏离：破坏性动作用 critical 填充而非 Accent（WinUI 没有内置危险按钮样式）、破坏性确认不设默认按钮（不让 Enter 一次带走破坏性操作）。
- 无头测试的硬约束：`Focus(NavigationMethod.Tab)` 不会产生 `:focus-visible`（窗口激活也没用），必须用 `window.KeyPress(Key.Tab, …, PhysicalKey.Tab, "")` 模拟按键；只跑 `build.ps1` 后 `dotnet test --no-build` 会用到测试工程 bin 下的旧 DLL，需先单独 `dotnet build` 该测试工程。
