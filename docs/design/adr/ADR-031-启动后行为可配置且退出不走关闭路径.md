# ADR-031：游戏启动后的行为可配置，启动退出不走关闭路径

- 状态：✅ 已接受
- 日期：2026-09-15
- 来源：用户提出的设置项「游戏启动后的行为」
- 相关：ADR-024（已保存设置只有一个写入方）、ADR-026（域内词汇留在域内）、ADR-027（判定结果不返回裸布尔）、ADR-028（客户端偏好按使用时机拉取）

## 背景

游戏启动成功后做什么，此前是写死的：`GameOperationJourney.StartGameAsync` 的成功分支固定「弹提示 → 等 600ms → `host.RequestMinimize()`」，Toast 文案也写死成「启动器已最小化到托盘」。用户没有任何选择权，而不想被最小化的人只能每次启动后自己把窗口找回来。

「窗口该怎么了」这一类偏好在本仓库已有先例——`CloseBehaviors`（关闭按钮的行为，`minimize` / `exit`），但它只覆盖关闭按钮。呈现侧的窗口动词也只有一个：`IGameOperationJourneyHost.RequestMinimize()`。

## 决策

1. **新增持久化设置 `afterLaunchBehavior`**，取值为 `AfterLaunchBehaviors` 的三个码：`keepOpen` / `minimize` / `exit`。默认 `minimize`，即既有用户升级后行为不变；归一化表拒绝未知值并回落到 `minimize`。

2. **设置页放在常规分区的「应用偏好」分组**，「关闭行为」的下一行——两行语义相邻，都是「窗口该怎么处理」。选项文案**复用既有的 `closeBehaviorMinimize` 与 `exitLauncher`**，只为「保持窗口打开」新增 `launchBehaviorKeepOpen`：同一个动作在两处以同一个词命名，比在四份资源里新造两条同义串更不容易日后漂开。

3. **规则留在旅程里**：`ApplyAfterLaunchBehaviorAsync` 按传入快照的 `Settings.AfterLaunchBehavior` 分派。快照在设置保存后会被刷新（`ShellLifecycle.HandleSettingsSavedAsync` → 刷新），因此改完设置立刻启动就生效，不需要重启。

4. **呈现层仍是两个单用途窗口动词**（`RequestMinimize` / `RequestExit`），而不是一个传动作码的方法。旅程说规则，宿主说效果；让宿主收到字符串码，等于把「这个码意味着对窗口做什么」的理解漏回视图层。

5. **启动退出刻意绕开关闭路径**：`MainWindow.ExitAfterLaunch()` 不走 `PerformClose()`。后者会把关闭意图交给已保存的 `CloseBehavior` 解释，用户若在那里选的是「最小化到托盘」，「启动后退出」就会退化成一次静默的托盘隐藏——设置看起来生效了，实际什么也没发生。退出直接走 `TryShutdown()`，与 `PerformClose` 的退出分支共用抽出的 `RequestShutdown()`。

6. **三条路径的提示各不相同**，且退出同样留 600ms 再走：保持窗口「游戏正在启动。」、最小化「…已最小化到托盘。」、退出「…启动器即将退出。」。退出若不先停一拍，窗口消失得快到用户拿不到「点到了」的回执；而沿用「已最小化到托盘」的文案则是明着说假话。

## 被否决的替代方案

**把 `RequestMinimize()` 换成 `RequestAfterLaunchAction(string behavior)`**：宿主拿到的是字符串码，呈现层就得自己解释每个码对窗口意味着什么，规则从旅程漏到视图；两个动词更贴合现有边界。

**复用 `PerformClose()` 走关闭路径**：见决策 5，会把新设置变成静默空操作，而这是最难被发现的那类缺陷——界面显示生效、行为没有。

**为「最小化」和「退出」各造一条新串**：四份资源里多两条与既有串同义的字，改一处漏三处的风险大于复用带来的耦合。

**未知值抛 `ArgumentOutOfRangeException`**（`ReportUpdateCheck` 等 switch 的写法）：那些 switch 遍历的是域内枚举，穷尽性可验证；这个值来自磁盘或代码构造的快照，归一化才是它的守卫，回落到出厂行为比让启动失败合适。

**退出时不显示提示，直接结束**：少一次短暂的 Toast，但用户从点击到窗口消失之间没有任何可见回执。

## 后果

- 常规设置页多一行「游戏启动后的行为」，默认「最小化到托盘」；行为变化只发生在用户显式改过之后。
- 启动退出后托盘图标一并消失，这是「退出启动器」的题中之义；想保留托盘的用户应选「最小化到托盘」。
- 「游戏退出后恢复启动器窗口」不在本次范围：`GameProcessTracker` 有进程退出数据，但没有 UI 接线，那是另一个特性。
- 守卫：`GameOperationJourneyTests`（保持窗口时两个窗口动词都不被触碰、退出请求退出且文案不承诺托盘、未知值回落最小化）、`GameOperationsViewModelTests`（宿主动词到达正确的事件）、`MainWindowHeadlessTests.WindowState`（`CloseBehavior = Minimize` 时启动退出仍然真的关闭——`Closed` 事件在真实关闭时触发、托盘隐藏时不触发，`IsVisible` 分不开这两者）、`LauncherSettingsServiceTests`（往返、非法值回落、旧 JSON 缺字段回落）、`UiStyleContractTests.Settings`（常规分区的绑定清单）、`ResxResourceContractTests`（键数 558 → 563）。
- 文案：新增 `launchBehavior`、`launchBehaviorDescription`、`launchBehaviorKeepOpen`、`gameLaunched`、`gameLaunchedExiting` 五个键（四语），并复用 `closeBehaviorMinimize` 与 `exitLauncher`。常规分区是设置页的默认分类，`settings-overlay.png` 金标准基线已随之重生。
