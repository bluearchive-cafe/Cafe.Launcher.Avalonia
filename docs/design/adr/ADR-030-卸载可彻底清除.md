# ADR-030：卸载可连整个安装目录一起清除，快捷方式与结果反馈同步补齐

- 状态：✅ 已接受
- 日期：2026-09-15
- 来源：用户在三轮讨论中提出的三件事（复选框、标准卸载也删快捷方式、统计完整卸载的目录大小）
- 相关：ADR-015（对话框家族统一框架）、ADR-021（保留操作后端接缝）、ADR-026（域内词汇留在域内）、ADR-027（确认后的拒绝必须有可见反馈）、ADR-029（预检失败不再静默）

## 背景

对照官方启动器 v1.7.2 的卸载实现（Electron，`handle-start-uninstall`）可以看出它删到什么程度：清单内文件 + `manifest.json` + `game-launcher-config.json`，**仅此而已**——游戏目录本身、清单外的残留、`*.tmp` 暂存、空目录、桌面快捷方式、Wine/UMU 兼容前缀全部留在原地。移植版沿用了同一范围，于是用户卸载后看到的是一堆残骸，还得手动去删目录和快捷方式。

同时，上一轮复核发现卸载的终态没人消费：`GameOperationJourney.ConfirmUninstallAsync` 拿到 `GameUninstallService.UninstallAsync` 的结果后既不检查也不呈现，逐文件删除撞上占用/权限时用户什么也看不到（同 ADR-027/029 那一类「点了没反应」，只是这次在**执行结果**这一层）。加入「彻底清除」会让删除面更大、更容易撞上失败，把结果继续丢掉就更说不过去。

## 决策

1. **确认框多一个可选勾选项**：`ConfirmDialog`（ADR-015 的类型化门面）新增一个可选行槽（`OptionText` / `IsOptionChecked`，未设 `OptionText` 时整行折叠），卸载确认框接上它。默认**不勾选**，且每次打开都重置——破坏性选项不预置，用户必须主动勾。9 处 `ConfirmDialog` 用量、3 个按钮、无图标等既有解剖契约全部不变，修复确认框的 golden 基线也不受影响。
2. **标准卸载也删桌面快捷方式**：删除属于「卸载成功」的一部分（清单与状态文件都删掉之后才执行）；中途失败则保留（游戏可能还在）。best-effort——桌面本来没有、系统不支持都不算失败，失败只记日志。命名按创建侧同一套计算重算（本地化显示名 / `.lnk` 与 `.desktop`），因此不依赖游戏文件是否还在。已知限制：切换界面语言后创建的旧名快捷方式不会被命中，这个语言敏感性在创建侧同样存在。
3. **「彻底清除」删两个目标**：整棵安装目录（连清单外残留、`*.tmp`、空目录）与本启动器托管的兼容子树 `compatibility/<gameId>`。用户自定义的 Prefix 只在该子树内才删；在子树外则保留，并在完成文案里说明——它是用户自选的任意目录，可能与别的东西共用，删它是另一件事。
4. **在确认框里显示将删除的目录大小，但对话框先弹、尺寸后到**：复用同一个「目标计算」同时服务测量与删除，所以显示多少就是随后会删多少。测量只读元数据、逐条容错（取不到的条目按 0，不让展示数字把对话框搞崩）、跳过 reparse point（与删除口径一致），数字用既有的 `FileSizeFormatter` 呈现。**测量必须先于用户看不见的那段时间，而不是挡在对话框前面**：落地首版把测量放在 `Show(...)` 之前，实测在 37,653 个文件 / 24 GB 的安装上要 3.4 秒——用户点击卸载后「没反应」，关掉设置页之后对话框才冒出来。现在的顺序是先显示带「正在统计大小…」的标签并立刻弹框，测量回来后把数字换上去（用户已经关掉/确认就不再回填）。
5. **终态必须落地**：`ConfirmUninstallAsync` 把执行结果交给既有的 `ShowOperationResult`，与修复、恢复同形——成功有回声，失败有错误提示。
6. **递归删除自己遍历**，不用 `Directory.Delete(path, recursive: true)`：实测 Windows 上树内只要有一个 junction/符号链接，后者就抛 `UnauthorizedAccessException`（`RemoveDirectoryRecursive`），一次可预期的布局就能让整棵删除失败。显式遍历把链接按链接本身删掉（不跟随进目标）、只读文件先摘属性、自底向上删空目录。守卫（越界、盘根、reparse point 目标）另收在 `DirectoryTreeDeleter.EnsureDeletable` 里，**预检先跑一次**：拒绝就什么都不删，不留半删状态；删除时再跑一次，两次之间被换成链接这种竞争折算成既有的 IO 失败路径上报。
7. **词汇留在域内**：`UninstallScope { ManifestFilesOnly, ThoroughCleanup }`（ADR-026 先例）。调用方（VM）把界面上的勾选一次性翻译成范围，执行层不再看布尔。

## 被否决的替代方案

**给 `UninstallAsync` 加一个 `bool thoroughCleanup`**：调用点看不出这个布尔是什么，且与 ADR-027 对裸布尔的取舍相悖；枚举还为将来第三种范围留了位置。

**照删用户自定义的 Prefix**：字面上更符合「彻底」，但那个路径可能是与他人共用的 Wine 瓶，删除范围不受本启动器控制。取「只删受管位置」并把保留事实说出来。

**用 COM 结构匹配（读 `.lnk` 目标）来删快捷方式**：能覆盖改过名的快捷方式，但会顺带删掉用户自建的第三方快捷方式，而 Linux 的 `.desktop` 的 `Exec` 指向启动器而非游戏，还得额外启发式。取「按创建时的计算重算名字」。

**先测完再弹框（落地首版的做法）**：得到的是单一定长文案，但把 3.4 秒的目录遍历放在了用户点击与对话框出现之间——实测就是「点了没反应，关掉设置页后对话框才弹出」。改成先弹框、后回填。

**勾选时才异步测量（标签显示「统计中…」再回填）**：常见路径（不勾选）省一次遍历，但用户勾了之后仍要等同样的 3.4 秒才看到数字，且多一个状态转换。取「打开对话框就开始测、数字在用户读完正文前几乎总是已经到位」。

**给卸载单独写一段 `DialogSurface` 分支**：会破坏 ADR-015 的类型化门面，并让 `ConfirmDialogUsages_ExposeNoDeadAnatomyProperties`（9 处）、`DialogsOverlay_DialogsUseHairlineFooterForActions`（1 处 Basic）两条计数契约各改一次。

**新增一个 `GameOperationStage` 表示清扫阶段**：`ApplyProgress_ForEveryStage_ProducesLocalizedPresentation` 会自动遍历所有阶段并要求有本地化标题，新增值必须补映射；清扫复用了 `Uninstalling`。

## 后果

- 卸载确认框多一个默认不勾的「彻底清除」，勾选后整个安装目录与受管 Prefix 一起消失；对话框同时给出这两个目录的实测大小。
- 标准卸载从此也清掉桌面快捷方式（行为变化：卸载后重装不会自动恢复快捷方式，界面上的「添加桌面快捷方式」仍在）。
- 卸载成功/失败都有可见反馈，不再有「执行结果无人消费」。
- 完成文案有三态：清干净用 `uninstallCompleted`，Prefix 主动保留用 `uninstallCompletedKeptPrefix`，**有个别项目删不掉**用 `uninstallCompletedWithLeftovers`（点名路径，完整清单进日志）。第三种是实机回归逼出来的：删不掉的项目不该让一次已经完成的卸载变成「卸载失败」——manifest 与两个状态文件都已删除，游戏确实卸载了，但剩下的东西必须说出来（见「已知限制」）。
- 守卫：`DirectoryTreeDeleterTests`（越界/盘根/reparse point 拒删、树内链接只删链接且目标存活、只读文件也能删——reparse 用例经 junction 回退，在 Windows 上真的跑起来；另有「删不掉的条目不影响其余删除、按路径交回调用方」与「全删干净时回报为空」两条）、`DirectorySizeProbeTests`（求和/缺失/空白/跳过链接）、`GameShortcutServiceTests`（删除命中并报告、缺失报 NotFound、目标目录为空报不支持）、`GameUninstallServiceTests`（标准路径删快捷方式、清单删除失败保留快捷方式、彻底清除删整棵树与受管子树、自定义前缀被保留并说明、测量与实际一致、游戏根是链接时守卫拒绝且不删任何东西）、`GameOperationJourneyTests`（范围转发、成功、返回失败与**抛出**三条路径都要有可见反馈、测量透传）、`GameOperationsViewModelTests`（每次打开重置勾选、标签含两个尺寸、勾选映射到范围）、`MainWindowViewModelTests.GameOperations`（勾选经真实接线到达执行层）、`UiStyleContractTests.Dialogs`（可选项的本地化名与双向绑定）。
- 文案：新增 `uninstallThoroughCleanupOption`、`uninstallCompletedKeptPrefix`、`uninstallCompletedWithLeftovers` 三个键（四语），并改写 `uninstallConfirmText` 第三行——原文「只会删除…」在勾选后就是假话，现在如实列出标准卸载会删的东西（含桌面快捷方式）。资源键总数 555 → 557 → 564。

## 已知限制

- 自定义 Prefix 落在受管子树之外时被保留，只在完成文案里说明，界面上没有「也把它删掉」的入口——若将来要加，应先解决「用户自选目录的删除范围」这个更危险的授权问题。
- Prefix 为 0 时选项标签仍会写出 `Prefix（0 B）`，属文案上的小瑕疵，换来的是单一定长串与不做动态回填。
- **反作弊留下的目录项用户态删不掉**：Blue Archive 的反作弊会在 `BlueArchive_Data\StreamingAssets` 下留 `Xigncode:{GUID}` 条目。2026-09-15 实机回归逐条排除过：普通路径、`\\?\` 前缀、`DeleteFileW`/`RemoveDirectoryW`、`cmd rd /s /q` 全部失败，且该条目没有 8.3 短名——`GetFileAttributesW` 报 `ERROR_FILE_NOT_FOUND`、`RemoveDirectoryW` 报 `ERROR_DIRECTORY`，因为它被 Win32 读成「`Xigncode` 文件的 `{GUID}` 数据流」。启动过游戏的安装因此删不掉最后一层目录骨架。这不是启动器能修的：`DirectoryTreeDeleter` 现在把这类条目当成「删不掉的项目」如实回报，而不是抛父目录那句无信息量的「目录不是空的」；完成文案点名路径并提示重启后可能可删。残留字节只会在游戏正常退出、反作弊自行清理时消失，启动器不做也做不到更彻底的处理。
