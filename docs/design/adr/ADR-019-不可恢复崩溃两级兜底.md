# ADR-019: 不可恢复崩溃采用同进程窗口与隔离报告模式两级兜底

- 状态：**已接受**（2026-09-08；grill-with-docs 决策与 A 版原型确认；同日复核补充来源→层级映射与快照兜底）
- 背景：现有 `ErrorHandlingService` 的严重错误覆盖层允许用户继续使用，无法承载进程已不可信时的退出语义；入口逃逸异常、Avalonia 调度器异常及 `AppDomain` 未处理异常还可能发生在主窗口不可用或尚未建立时。崩溃界面本身也不能依赖完整业务依赖图。
- 决策：
  - 保留现有可恢复严重错误行为，新增独立 `IFatalCrashService` 入口，仅用于不可恢复崩溃。
  - 层级由来源决定，不由进程内是否恰好存在 UI 订阅者决定：主界面仍健康时，在当前进程中隐藏主窗口并显示独立 `CrashReportWindow`（tier-1，入口只有 `IFatalCrashService.HandleFatalCrash`）；入口逃逸、Avalonia 调度器、`AppDomain` 未处理异常与诊断初始化失败（tier-2）先持久化崩溃快照，再以 `--crash-report <path>` 启动同一可执行文件的最小化报告模式，即使此刻 UI 仍订阅着致命事件也不改走窗口——崩溃进程即将被放弃，报告必须比它活得久。
  - tier-1 需要 UI 健康，因此只可能由启动器自身逻辑的显式判定进入。当前没有这样的生产判定，tier-1 由调试面板的模拟入口行使；调试面板的「模拟致命崩溃」「模拟未处理异常」两个按钮是两条链路的正式行使者，只存在于 Debug 构建（`IsDebugFeaturesEnabled` 在 Release 下为 false），不构成用户可达的退出入口。
  - 崩溃来源是封闭集合 `CrashOrigin`（入口逃逸、调度器、进程域、诊断初始化、调试模拟），快照与日志只写入它映射出的固定标签，不接受调用方自由文本。
  - 同一次进程生命周期只接受首个崩溃为主报告；后续失败追加到旁路日志，避免重复弹窗和重启风暴。未观察任务异常只记录日志并标记为已观察，不弹窗。
  - 崩溃窗口采用已确认的 A 版信息层级：默认只显示友好说明、报告编号、时间和版本；技术详情放在默认折叠区域；仅提供打开日志目录、复制详情和退出启动器，不提供继续、重启或在线上传。「打开日志目录」指向启动器日志（`unified.log`）所在的数据目录。
  - 快照只记录诊断所需的异常、应用版本、操作系统与 UI 语言；用户目录统一替换为 `%USERPROFILE%`，不采集环境变量或命令行。主目录不可写时降级到临时目录；两处都写不进时仍以不带路径的 `--crash-report` 启动报告进程，由其显示「快照不可读」报告，保证任何一次不可恢复崩溃都有界面。保留最近 10 份且最长 30 天，清理同时覆盖主目录与临时降级目录。
- 后果：不可恢复崩溃始终以非零退出码结束；隔离报告模式绕过单实例互斥和完整依赖注入，减少崩溃链式失败。代价是增加一套最小应用入口、快照协议和清理策略，需由单元测试、Headless UI 测试及 A 版黄金截图共同守护。
