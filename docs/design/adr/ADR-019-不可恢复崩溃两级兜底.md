# ADR-019: 不可恢复崩溃采用同进程窗口与隔离报告模式两级兜底

- 状态：**已接受**（2026-09-08；grill-with-docs 决策与 A 版原型确认）
- 背景：现有 `ErrorHandlingService` 的严重错误覆盖层允许用户继续使用，无法承载进程已不可信时的退出语义；入口逃逸异常、Avalonia 调度器异常及 `AppDomain` 未处理异常还可能发生在主窗口不可用或尚未建立时。崩溃界面本身也不能依赖完整业务依赖图。
- 决策：
  - 保留现有可恢复严重错误行为，新增独立 `IFatalCrashService` 入口，仅用于不可恢复崩溃。
  - 主界面仍健康时，在当前进程中隐藏主窗口并显示独立 `CrashReportWindow`；入口逃逸、调度器和 `AppDomain` 未处理异常先持久化崩溃快照，再以 `--crash-report <path>` 启动同一可执行文件的最小化报告模式。
  - 同一次进程生命周期只接受首个崩溃为主报告；后续失败追加到旁路日志，避免重复弹窗和重启风暴。未观察任务异常只记录日志并标记为已观察，不弹窗。
  - 崩溃窗口采用已确认的 A 版信息层级：默认只显示友好说明、报告编号、时间和版本；技术详情放在默认折叠区域；仅提供打开日志目录、复制详情和退出启动器，不提供继续、重启或在线上传。
  - 快照只记录诊断所需的异常、应用版本、操作系统与 UI 语言；用户目录统一替换为 `%USERPROFILE%`，不采集环境变量或命令行。主目录不可写时降级到临时目录；保留最近 10 份且最长 30 天。
- 后果：不可恢复崩溃始终以非零退出码结束；隔离报告模式绕过单实例互斥和完整依赖注入，减少崩溃链式失败。代价是增加一套最小应用入口、快照协议和清理策略，需由单元测试、Headless UI 测试及 A 版黄金截图共同守护。
- 原型：`prototypes/crash-window-design.html?variant=a`。该原型作为视觉决策记录保留，不随生产实现删除。
