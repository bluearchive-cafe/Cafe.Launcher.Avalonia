# ADR-047：改名跨版本的升级迁移由安装器清理旧可执行文件并启动新版本

- 状态：✅ 已接受
- 日期：2026-10-07
- 来源：用户报告 [issue #23](https://github.com/bluearchive-cafe/Cafe.Launcher.Avalonia/issues/23)：安装 1.1.1 后「关于」回到 1.1.0，并再次出现更新提示
- 相关：[ADR-037](ADR-037-Windows自更新走独立helper且以SHA256SUMS为信任锚.md)、[ADR-043](ADR-043-程序集与命名空间同名.md)

ADR-043 把宿主可执行文件从 `Cafe.Launcher.Avalonia.exe` 改名成 `Cafe.Launcher.exe`，同时刻意保留 Inno `AppId`、安装标记与数据目录。名字改对了，但当时写下的「自更新不受影响」只论证了**资产选择**按后缀匹配（`_setup.exe` / `_win-x64.zip`），漏掉了应用阶段的两条名字依赖：

- `[Files]` 只添加与覆盖本版发布的文件。旧版那个名字不同的 exe 不在本版清单里，升级完成后它**仍然可运行**：既有的桌面快捷方式继续启动它，用户看到的「关于」因此回到 1.1.0；而它又比已安装的版本旧，更新提示于是再次出现。
- helper 的重启目标来自启动它的进程名（`Environment.ProcessPath`），也就是**旧版**的名字。升级后该名字可能已经不存在：`Apply completed` 照样成立，但重启要么拉起残留的旧 exe，要么什么都拉不起来。

issue #23 把两条都钉住了，证据齐全：`update-apply.log` 只有一次 `Apply completed (mode=Installer, elapsed=17.8s)` 且没有失败行；比它晚 0.5 秒，`unified.log` 里出现一个 `Version: 1.1.0` 的新会话（就是 helper 拉起来的）；安装目录里 `Cafe.Launcher.Avalonia.exe`（1.1.0.0）与 `Cafe.Launcher.exe`（1.1.1.0）并存；用户的桌面快捷方式指向旧的那个。

## 决定

1. **安装器在每次安装时删除改名前的可执行文件**（`[InstallDelete]`，就是 ADR-043 那一个历史名字）。旧版本不能以任何形式留在安装目录里可运行——桌面快捷方式、任务栏固定项、helper 的重启都会找到它。
2. **静默安装（应用内更新走的那条路）由安装器自己启动新版本**（`[Run]` 的 `skipifnotsilent` 条目）；交互安装保持结束页勾选框，原 `skipifsilent` 条目不变。这条是给**旧版 helper** 兜底的：跑 setup 的 helper 永远来自已安装版本，它重启的是它被告知的名字，而那个名字刚被第 1 条删掉。
3. **helper 的启动目标按目录里实际存在的文件解析**：优先命令行下发的名字，其次产品 token 名（`UpdateApplyPlan.LauncherExecutableName`），两者都没有就按启动失败上报，绝不猜。`Apply completed` 改到**启动成功之后**才写，并在启动前记一行 `Starting the launcher: <path>`，避免日志再次读成「成功」。

## 后果

- 便携版 ≤ 1.1.0 的应用内更新**无法事后修复**：那时的 helper 用旧名字校验包内布局，改名后的 zip 里没有它，于是停在 `PackageLayoutInvalid`、原地不动。这部分用户需要手动下载一次；下一次改名不会再出现同样问题，因为解析规则已经在 helper 侧。
- 打包命名守卫有且只有一个例外：`.iss` 里允许出现一次历史上的 exe 名，且必须是 `[InstallDelete]` 的清理目标（`AssemblyNamingContractTests.ReleaseAssets_UseTheHostProductToken` 把出现次数钉死为 1，`InstallerContractTests.IssInstaller_RemovesThePreRenameLauncherOnUpgrade` 钉住它是清理项而非第二套身份）。
- 用户自建的快捷方式仍可能指向旧名字；旧文件删除后它会失效，用户改用开始菜单里那个（安装器始终重建）即可。产品不会替用户改写不是自己创建的快捷方式。
- 便携换位与安装版重启现在共用同一条解析规则，因此「同一个安装目录里只应有一份可运行的启动器」重新成为不变量。

## 被否决的方案

- **给旧名字留一个硬链接或副本指向新 exe。** 等于把 ADR-043 要消掉的名字永久留在安装目录，也让上面那条不变量永远不成立；用户还会在任务管理器里看到旧名字。
- **由 helper 比较候选 exe 的版本，选较新的那个重启。** 需要读 PE/程序集版本，仍然是在猜；「安装器删掉旧名字 + 按目录里存在的名字启动」把猜测本身消掉了。
- **让 helper 从 release 资产名推导新版本的可执行文件名。** 资产前缀与 exe 名不是同一个东西（macOS/Linux 的资产名与可执行名不同），推导会在别的平台上错。
