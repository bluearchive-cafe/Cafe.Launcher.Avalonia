# ADR-035：游戏会话状态可见——启动后看护与会话状态行

- 状态：✅ 已接受（2026-09-22）
- 日期：2026-09-22
- 来源：用户报告「使用第三方运行器启动时提示『游戏正在启动』后无法知晓游戏的运行状态」
- 相关：ADR-031（启动后行为可配置；「游戏退出数据没有 UI 接线」是它记下的范围外项，本 ADR 就是那个特性）、ADR-032（游戏进程按名字家族识别）、ADR-027（拒绝必须可见）

## 背景

`GameRuntime.LaunchAsync` 把运行器进程（`umu-run`/`wine`，原生即游戏本身）spawn 出来就报成功：Wine/Proton 内部失败（Prefix 损坏、缺依赖、Proton 选错）会让运行器数秒内带非零码退出，而启动器已弹过「游戏正在启动」并按设置最小化或退出。`GameProcessTracker` 一直在采集退出数据（`Exited` + `GameLaunchExitInfo`：退出码、时长、运行器），但 src/ 中没有消费者；名字家族扫描只在破坏性操作的写边界当闸门。启动中、运行中、已退出三件事界面上都看不见。

## 决策

1. **会话看护 `GameSessionMonitor`**（`Features/GameOperations/`，`IGameSessionMonitor.cs` + 实现）：状态机 `Idle → Starting → Running → Exited/StartFailed`；旅程只在启动成功分支调用 `BeginSession(runnerId, knownExeNames)`。原生启动即运行中（被跟踪宿主就是游戏，句柄活着即成立）；运行器启动先落「启动中」，轮询 `ProcessService.FindRunningExeNamesAsync` + `BelongsToFamily`（ADR-032 判据，五秒一拍），家族现身转「运行中」。
2. **宿主退出按家族是否出现过分类**：从未出现 → `StartFailed`；出现过 → 正常退出。退出码原样透传，不做成败解读之外的修辞。
3. **运行中宿主退出不立即定论**：先做最后一次家族扫描，真身是启动参数里另一个可执行文件且仍在跑则维持「运行中」（ADR-032 家族判据正是为它存在的）；整体扫描失败也维持「运行中」并恢复轮询，等待成功扫描确认。核实带会话版本号，期间重新 `BeginSession` 的旧核实作废。
4. **`LastExit` 归属当前被跟踪进程**：`Register` 时清零（`GameProcessTracker`），`BeginSession` 时 `LastExit` 非空即本局宿主已亡、由首扫后定论；`IGameProcessTracker` 新增 `TrackedProcessExited`（每次 Register 至多一次）。
5. **运行期看护**（2026-09-22 修正，用户报告「游戏进程退出后仍然显示游戏运行中」）：宿主可能在游戏起来后就退出（ADR-032 实测：原生加载器宿主如此；运行器也有提前脱离形态），因此家族现身、或宿主退出核实仍在跑时，不停轮而按同一节奏继续扫；家族**连续两轮**缺席（约十秒）才判定退出——单个缺席轮可能是枚举抖动或游戏短暂自重启（打补丁），不认账；枚举失败不计入缺席；底层扫描器传播整体失败，会话监控保留未知并重试，闸门则由 GameProcessTracker 单独应用放行策略（2026-10-20 补齐真实适配层回归）。轮询判定的退出**没有可归属的退出码**（宿主的退出码属于宿主），按不带退出码的「游戏已退出」呈现（`gameSessionExitedNoCode`），不硬凑数字。
6. **启动失败的呈现留在旅程**（`GameOperationJourney.NotifySessionStartFailed`）：**先恢复窗口再报错**——Toast 渲染在窗口内，窗口最小化在托盘等于没报（ADR-027）。宿主接口加 `RequestShow()`，`GameOperationsViewModel` 转发为新事件 `ShowRequested`，`MainWindow` 订阅后走既有 `ShowWindow()`（托盘/二次实例同款路径，ADR-031 决策 4 的形状）；错误 Toast 与警告级诊断日志（含退出码与时长）同时落地。
7. **游戏正常退出不打扰**：不恢复窗口、不弹 Toast，只把状态行静默换成「游戏已退出（退出码 X）」；「游戏退出后自动恢复窗口」仍是 ADR-031 记录的范围外项（用户裁定）。
8. **状态行放在控制面板**：紧凑布局（版本/启动检查/网络 同一行）行首与「仅按钮」布局的启动按钮左侧各一条，绑定 `Operations.GameSessionStateText` + `Operations.IsGameSessionVisible`；**空闲时整行隐藏**，无会话时布局与金标准基线不受影响。语言切换随 `RefreshLocalizedText` 重排文案，`StartFailed` 的恢复窗口与错误 Toast 不重放——一次性动作与文案呈现分开。
9. **判据同源**：`RunningGameGate.ResolveKnownProcessNames`（自 `DownloadSession` 私有方法提取）读本地 config `name`+`params`，缺失时回退远端声明的同两个字段；下载闸门与启动看护共用。启动成功路径本地配置必有宿主名（`GameLaunchTargetResolution` 已据此解析目标），家族集合不会为空。
10. **通知合并**：`StateChanged` 只报值得报告的状态；一次 `BeginSession` 轮内同步完成的快速迁移合并为一条携带最终态的通知；ViewModel 只在 `StartFailed` 时向旅程要动作，其余状态只换文案。

## 备选方案

- **把运行器提前退出做成启动失败回报**（同步改 `LaunchAsync` 返回值）：启动调用早已返回、窗口已最小化，同步路径无处可去；看护是异步事实，只能在异步侧表达。
- **复用 `IGameProcessTracker.FindRunningGameProcessesAsync`**：它句柄优先的语义为破坏性闸门设计，wine 宿主活着而游戏本体未起时会假阳性；看护要回答的是「游戏自己的进程出现过没有」。
- **按退出码判成败**：wine 会转发游戏自己的退出码，正常退出也可能非零，零码秒退未必成功；家族是否出现过是强得多的信号，退出码只透传。
- **游戏退出时恢复窗口/弹通知/托盘气泡**：对「最小化到托盘等游戏」的用户是打扰（ADR-031 已记为另一个特性）；跨平台通知还引入 Linux 通知守护进程依赖，而失败时恢复窗口 + 窗口内 Toast 已必然送达。
- **常驻全局面板轮询**：终态后继续轮询只为一个指示符，成本与价值不成比例；看护只在 `Starting`/`Running` 轮询。

## 后果

- 第三方运行器「报成功其实没起来」不再静默：运行器提前退出会在数秒内恢复窗口并报「游戏未能启动（退出码 X）」，退出码与时长进诊断日志。
- 界面首次有了会话状态：启动中 / 游戏运行中 / 游戏已退出（退出码 X）/ 游戏未能启动（退出码 X），空闲时隐藏。
- `IGameProcessTracker` 新增 `TrackedProcessExited`；`LastExit` 收窄为「最近一次 Register 的进程的退出」。
- `RunningGameGate.ResolveKnownProcessNames` 是「闸门认哪些名字」的唯一出处，`DownloadSession` 与 `GameLaunchService` 共用。
- 启动器重启后识别不到外部已在运行的游戏（无会话句柄，看护从 Idle 开始），破坏性闸门兜底；`AfterLaunchBehavior = exit` 时进程已退出，无从反馈。均为有意范围外。
- 守卫：`GameSessionMonitorTests`（原生即运行中、家族现身分类运行中、宿主先亡分类启动失败、运行中退出且家族仍在时维持运行中并重启轮询、家族连续两轮缺席判定退出且无退出码、单个缺席轮不认账、枚举失败不计入缺席、宿主先亡后游戏退出由轮询收口、Register 前竞态由 LastExit 收口、扫描异常继续等、终态只落一次、重开清零）、`GameProcessTrackerTests`（退出事件各路径恰好一次、订阅前退出由 LastExit 携带、重开清零）、`GameOperationJourneyTests`（成功才 BeginSession 且带运行器与家族、失败不建会话、启动失败先恢复窗口再报错、退出信息缺失按 -1 报出）、`GameOperationsViewModelTests`（状态行各态呈现、无退出码的退出行、正常退出静默、启动失败恢复窗口 + 错误 Toast）、`ResxResourceContractTests`（键数 574 → 579）。
- 文案：新增 `gameSessionExited`、`gameSessionExitedNoCode`、`gameSessionRunning`、`gameSessionStartFailed`、`gameSessionStarting` 五键（四语）。
