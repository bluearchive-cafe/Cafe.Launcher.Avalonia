# ADR-035：游戏会话状态可见——启动后看护与会话状态行

- 状态：✅ 已接受
- 日期：2026-09-22
- 来源：用户报告「使用第三方运行器启动时提示『游戏正在启动』后无法知晓游戏的运行状态」
- 相关：ADR-031（启动后行为可配置，其中第 44 行明确「游戏退出数据没有 UI 接线是另一个特性」——本 ADR 就是那个特性）、ADR-032（游戏进程按名字家族识别）、ADR-027（拒绝必须可见）

## 背景

启动成功的判定只覆盖 `Process.Start` 那一刻：`GameRuntime.LaunchAsync` 把运行器进程（`umu-run`/`wine`，原生即游戏本身）spawn 出来就报成功。对第三方运行器而言，这一刻之后的事实无人过问——Wine/Proton 内部失败（Prefix 损坏、缺依赖、Proton 选错）会让运行器在几秒内带着非零码退出，而启动器已经弹了「游戏正在启动」并按设置最小化到托盘或退出。用户手里只有一个无法兑现的承诺。

`GameProcessTracker` 其实一直在采集退出数据（`Exited` 事件 + `GameLaunchExitInfo`：退出码、时长、运行器），但整个 src/ 没有任何消费者；名字家族扫描只在破坏性操作（卸载、下载/安装/修复）的写边界当闸门用，从不同馈界面。游戏真的起来、正在运行、后来退出了——这三件事界面上都看不见。

## 决策

1. **新增会话看护 `GameSessionMonitor`**（`Features/GameOperations/`，`Features/GameOperations/IGameSessionMonitor.cs` + 实现），状态机 `Idle → Starting → Running → Exited/StartFailed`：
   - 旅程在启动**成功分支**调用 `BeginSession(runnerId, knownExeNames)`——失败路径没有会话可看护；
   - **原生启动即运行中**：被跟踪的宿主就是游戏本身，句柄活着即成立，无需等扫描确认；
   - **运行器启动先落「启动中」**：宿主只是 wine/umu-run，「游戏起来了」要等游戏进程家族现身——轮询用与破坏性闸门同一份名字家族扫描（`ProcessService.FindRunningExeNamesAsync` + `BelongsToFamily`，ADR-032 的判据），五秒一拍，看到家族即「运行中」（此处的「并停止轮询」已被决策 7 修订：家族现身转入运行期看护，扫描继续）；
   - **宿主退出时按「家族是否出现过」分类**：从未出现 → `StartFailed`（启动失败）；出现过 → 正常退出。退出码原样透传给界面，不做成败解读之外的修辞；
   - **运行中宿主退出不立即定论**：先做最后一次家族扫描——母进程退出、真身是启动参数里另一个可执行文件还在跑的情形（ADR-032 家族判据正是为它存在的）维持「运行中」；此后没有句柄可订阅，「游戏是否在跑」由各闸门回答。核实带会话版本号，期间重新 `BeginSession` 的旧核实作废；
   - **`LastExit` 归属当前被跟踪的进程**：`Register` 时清零（`GameProcessTracker`）。于是「Register 与订阅之间已退出」的竞态有了收口——看护 `BeginSession` 时 `LastExit` 非空即本局宿主已亡，由看护循环首扫后定论；`IGameProcessTracker` 同时新增 `TrackedProcessExited` 事件（每次 Register 至多一次）。

2. **「启动失败」的呈现规则留在旅程**（`GameOperationJourney.NotifySessionStartFailed`）：**先恢复窗口再报错**——Toast 渲染在窗口内，窗口还最小化在托盘就等于没报（ADR-027 的精神：拒绝必须送达）。窗口动词沿用 ADR-031 决策 4 的形状：宿主接口加 `RequestShow()`，`GameOperationsViewModel` 转发为新事件 `ShowRequested`，`MainWindow` 订阅后走既有 `ShowWindow()`（托盘/二次实例同款路径）。错误 Toast 与诊断日志（警告级，含退出码与时长）同时落地。

3. **游戏正常退出不打扰**：不恢复窗口、不弹 Toast，只在状态行静默换成「游戏已退出（退出码 X）」。这是用户裁定的边界——「游戏退出后自动恢复窗口」仍是 ADR-031 记录在案的范围外项。

4. **状态行放在控制面板**：紧凑布局的状态行（版本/启动检查/网络 同一行）行首与「仅按钮」布局的启动按钮左侧各一条，绑定 `Operations.GameSessionStateText` + `Operations.IsGameSessionVisible`。**空闲时整行隐藏**——无会话时布局与金标准基线不受影响。语言切换时状态行随 `RefreshLocalizedText` 重排文案，但 `StartFailed` 的恢复窗口与错误 Toast 不重放——那是状态变化时刻的一次性动作，文案呈现与动作表态分开。

5. **判据同源**：已知进程名解析从 `DownloadSession` 的私有方法提取为 `RunningGameGate.ResolveKnownProcessNames`（本地 config `name`+`params`，缺失时回退远端声明的同样两个字段），下载闸门与启动看护共用一份——「游戏在跑」的判据在启动路径与破坏性操作路径之间不会分叉。启动成功路径上本地配置必有宿主名（`GameLaunchTargetResolution` 已据此解析目标），家族集合不会为空。

6. **通知合并**：`StateChanged` 只报「值得报告的状态」——一次 `BeginSession` 轮内同步完成的快速迁移合并为一条携带最终态的通知；订阅方（ViewModel）只在 `StartFailed` 时向旅程要动作，其余状态只换文案。

7. **「运行中」的退役不能只压在宿主的退出事件上**（2026-09-22 修正，用户报告「游戏进程退出后仍然显示游戏运行中」）：运行期看护最初在家族现身时就停轮、此后只等宿主的退出事件——但宿主完全可能在游戏起来后就退出（ADR-032 实测：原生加载器宿主正是如此；运行器也有提前脱离的形态），此后既无句柄可订阅也无别的信号，游戏退出就永远停在「运行中」。修正后家族现身（及宿主退出核实仍在跑）时**转入运行期看护**：同一节奏继续扫，家族**连续两轮**缺席（约十秒）才判定退出——单个缺席轮可能是枚举抖动或游戏短暂自重启（打补丁），不认账；枚举没有答案不计入缺席（与闸门对「没有答案」的取舍一致）。轮询判定的退出**没有可归属的退出码**（宿主的退出码属于宿主、不属于游戏消失的这一刻），按不带退出码的「游戏已退出」呈现（`gameSessionExitedNoCode`），不硬凑数字。

## 被否决的替代方案

**把「运行器提前退出」也做成启动失败回报**（同步改 `GameRuntime.LaunchAsync` 的返回值）：启动调用早已返回、窗口早已按设置最小化，同步路径无处可去。看护是异步事实，只能在异步侧表达。

**复用 `IGameProcessTracker.FindRunningGameProcessesAsync` 做家族检测**：它「句柄优先」的语义是为破坏性闸门设计的（本会话句柄活着就视为在跑），而看护要回答的是「游戏自己的进程出现过没有」——wine 宿主活着但游戏本体未起时它会给出假阳性。看护直接用底层家族扫描，各自语义各自干净。

**按退出码判成败**（非零即失败）：wine 会转发游戏自己的退出码，正常退出也可能非零；反过来零码的秒退未必成功。家族是否出现过是比退出码强得多的信号，退出码只透传给用户。

**游戏退出时恢复窗口/弹通知**：对「最小化到托盘等游戏」的用户，游戏退出弹窗是打扰；ADR-031 已把「游戏退出后恢复窗口」明确记为另一个特性。本次只做状态行静默更新，打扰度由用户裁定。

**托盘气泡/系统通知**：跨平台系统通知引入新的平台面（Linux 通知守护进程依赖），而失败场景下恢复窗口 + 窗口内 Toast 已经必然送达。

**常驻全局面板轮询游戏状态**：会话结束后继续轮询只为一个指示符，成本与价值不成比例。看护在 `Starting` 与 `Running` 两态轮询（后者由决策 7 修正引入），终态后全部停止。

## 后果

- 使用第三方运行器启动时，「报了成功但其实没起来」不再静默：运行器提前退出会在数秒内恢复窗口并报「游戏未能启动（退出码 X）」，退出码与时长进诊断日志。
- 界面上第一次有了游戏会话的可见状态：启动中 / 游戏运行中 / 游戏已退出（退出码 X）/ 游戏未能启动（退出码 X），空闲时隐藏。
- `IGameProcessTracker` 新增 `TrackedProcessExited` 事件，`LastExit` 语义收窄为「最近一次 Register 的进程的退出」（新登记清零旧账）。
- `RunningGameGate.ResolveKnownProcessNames` 成为「闸门认哪些名字」的唯一出处，`DownloadSession` 与 `GameLaunchService` 共用。
- 启动器重启后无法识别外部已在运行的游戏（无会话句柄，看护从 Idle 开始）——破坏性操作的闸门仍然兜底；`AfterLaunchBehavior = exit` 时进程已退出，无从反馈。两者均为有意范围外。
- 守卫：`GameSessionMonitorTests`（原生即运行中、家族现身分类运行中、宿主先亡分类启动失败、运行中退出且家族仍在时维持运行中并重启轮询、家族连续两轮缺席判定退出且无退出码、单个缺席轮不认账、枚举失败不计入缺席、宿主先亡后游戏退出由轮询收口、Register 前竞态由 LastExit 收口、扫描异常继续等、终态只落一次、重开清零）、`GameProcessTrackerTests`（退出事件各路径恰好一次、订阅前退出由 LastExit 携带、重开清零）、`GameOperationJourneyTests`（成功才 BeginSession 且带运行器与家族、失败不建会话、启动失败先恢复窗口再报错、退出信息缺失按 -1 报出）、`GameOperationsViewModelTests`（状态行各态呈现、无退出码的退出行、正常退出静默、启动失败恢复窗口 + 错误 Toast）、`ResxResourceContractTests`（键数 574 → 579）。
- 文案：新增 `gameSessionExited`、`gameSessionExitedNoCode`、`gameSessionRunning`、`gameSessionStartFailed`、`gameSessionStarting` 五键（四语）。
