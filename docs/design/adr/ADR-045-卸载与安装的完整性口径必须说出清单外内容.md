# ADR-045：卸载与安装的完整性口径——清单之外的内容必须被说出来

- 状态：✅ 已接受
- 日期：2026-09-29
- 来源：用户反馈两条（「为什么删了游戏读取不到了但是文件还在」「点击下载之后假装忙活一下然后直接就让我进去了」），附日志导出 `CafeLauncher_Logs_20260929_204414`
- 相关：ADR-026（域内词汇留在域内）、ADR-027（确认后的拒绝必须有可见反馈）、ADR-029（预检失败不再静默）、ADR-030（卸载可彻底清除）、ADR-032（游戏进程按名字家族识别）

## 背景

ADR-030 落地时已知「标准卸载只删清单内文件 + 两个状态文件」，并把「彻底清除」做成**默认不勾**的可选项。当时没被量化的是这个范围的**相对大小**：启动器的文件清单只覆盖它自己安装的那一部分，而游戏的大头是游戏运行时自行下载的。

2026-09-29 的实测把差距钉死了：

- 我方清单（官方 `zip_online_config_json`，1.73.0）：**157 个文件、1,140,416,350 B ≈ 1.06 GiB**（`GameAssembly.dll`、`UnityPlayer.dll`、`xldr_..._loader_x64.exe`、9 个视频等）。
- 官方 `/api/launcher/game/config` 自己声明的 `decompression_size`：**18.5 GB**。
- 用户日志：`GameUninstall ... files: 157 / leftovers: 0` → 启动器报「卸载完成。」；约 51 分钟后 `GameDownload` 完成 → 30 秒后游戏启动成功。

两个用户可见的后果都由此而来：卸载后启动器读不到安装（两个状态文件已删）而盘上仍有 ~17.4 GiB（第一条）；重新安装只补回清单内的 1.06 GiB，游戏因为那 17.4 GiB 还在而立刻可玩（第二条）。启动器没有说谎——它按自己的定义完成了——但**它没有说出另一半事实**。

同时暴露两处「排查时会骗人」的书面凭据：

1. 卸载日志的 `leftovers: 0` 只在勾选彻底清除时才会被填充，标准卸载恒为 0——「0 残留」的假象恰好掩盖了「目录里还有 17 GiB」。同一行的 `files: 157` 是**计划**条数，被当成「删掉了 157 个」读。
2. 差异计数 `Manifest diff: N to download, M to delete` 走 Debug 级，而用户导出的日志默认 `logLevel: information`——最能解释「安装秒过」的那一行恰好被级别过滤掉了。

## 决策

1. **完成文案新增第三个事实，且走独立的一句**：标准卸载（`ManifestFilesOnly`）完成后，结果串在基础文案之后再追一句「标准卸载不删除安装目录本身。由游戏自行下载的内容不在启动器管理的文件清单内，不会随卸载删除；该目录仍位于：{0}。如需清理，请手动删除该目录。」基础四态（清干净 / Prefix 保留 / 有残留 / 残留+保留）一个都不改——第三个维度与其他事实互不包含，追一句即可，不再乘出组合态。判据只取「目录还在吗」，不去数里面还剩什么：文案陈述的是**范围**（清单外内容不随卸载删除），数条目要么多走一次目录枚举，要么在恰好空的目录上说出被当场证伪的话。目录确实已被删（彻底清除）时不出现这句。
2. **卸载确认框给出「将删除 / 不会删除」的对比**：`uninstallConfirmText` 增加占位符 `{2}`（清单文件合计字节数，来自预检结果新增的 `GameOperationResult.AffectedBytes`），文案从「文件清单中的文件数：{1}」改成「启动器管理的文件：{1} 个（{2}）」并明确列出「不会删除：安装目录中由游戏自行下载的其他内容」，指向下面的「彻底清除」。只报文件个数时，157 会被读成「整个游戏」。
3. **日志按实测与范围记录**：`ManifestFileRemover.DeleteAll` 改为返回实测结果（实际删除数 / 实际字节数 / 本来就不在盘上的条目数），卸载完成日志随之报 `scope`、`manifest files: N planned, M removed (B bytes), K already absent`，并且**只在彻底清除时**输出 `leftovers`，标准卸载改为输出 `directory retained: <路径>` 或 `(not present)`。删掉续传标记失败从静默吞掉改为 Warning 留痕。
4. **全新安装前先说明**：状态是「未安装」而目标目录已有条目时，开始安装前先弹一条信息性提示「该目录中已有内容：{0}。启动器只会下载并校验文件清单内的文件，目录中的其他内容不会被校验或替换」。判据是「启动器不认这份安装」+「盘上还有东西」同时成立；空目录、目录不存在、以及更新/修复路径都不提示（那些场景没有意外）。
5. **差异计数升到 Information**：`Manifest diff: N to download (B bytes), M to delete` 与 `Manifest diff: 0 files changed (already current)` 两条都从 Debug 改为 Info——它们是「这次安装到底干了多少」的唯一书面凭据。

## 被否决的替代方案

**把「彻底清除」改成默认勾选**：能一次性消掉残留，但破坏性选项预置会让「点一下卸载」变成删掉整个目录（含用户自己放进去的东西），与 ADR-030 的「破坏性选项不预置」直接相悖。取「默认范围不变 + 把范围说清楚」。

**在完成文案里报「目录还剩多少 GB」**：需要在删除之后再走一次 `DirectorySizeProbe`（37k 文件实测 3.4 秒），而这 3.4 秒正好落在用户等待「卸载完成」提示的那一段。宁可报事实（清单外内容仍在、路径在此）而不报一个会拖慢终态的数字；要数字的用户在确认框里已经看过对比。同一条理由也否掉了「数一数目录里还剩几个条目再决定要不要说这句」。

**把清单外内容纳入卸载删除范围**：启动器不知道它们的文件名、大小与版本，删它们等于按目录猜；ADR-030 已经把「整棵目录」这个选项放在用户手上（彻底清除），不替用户默认做决定。

**把安装前提示做成模态确认框**：与既有确认框家族（9 处用量、解剖契约）耦合，且这个问题不需要用户决策——只是一条「将要发生什么」的说明；信息性 toast 足够，且不动金标准基线。

## 后果

- 标准卸载的结果串多一句（含安装目录路径），用户第一次能看见「还有东西、在哪、怎么清」。
- 卸载确认框的第三行重写并新增 `{2}`；`GameOperationResult` 新增 `AffectedBytes`（预检与结果同义：启动器管理的文件集合计字节数）。
- 卸载完成日志的结构变化：`scope` / 实测删除数 / 实测字节数 / 缺失条目数 / `directory retained`（标准）或 `leftovers`（彻底清除）。标准卸载不再输出恒为 0 的 `leftovers`。
- 资源键 594 → 596（`uninstallCompletedDirectoryRetained`、`installOverExistingContentNotice`，四语；`uninstallConfirmText` 是同轮改写，不新增）。`ResxResourceContractTests` 的减速带常量与演进注释同步更新。
- 守卫：`GameUninstallServiceTests`（标准卸载必须点名目录 / 彻底清除不许点名 / 日志含 scope 与实测删除数且标准卸载不得出现 `leftovers` / 预检暴露清单字节数）、`GameOperationJourneyTests`（未安装 + 目录非空 → 提示且在最前；空目录、目录不存在、更新路径 → 都不提示）、`GameOperationsViewModelTests`（确认框含清单字节数、占位符全消费）、新增 `ManifestFileRemoverTests`（实测计数、缺失条目、只读文件、空清单）与 `InstallDirectoryContentTests`（不存在 / 空 / 只有空子目录 / 有文件 / 空白路径）。
- 已知限制：安装前提示是信息性的，不阻断也不询问；游戏自行下载内容的版本与完整性仍然只有游戏自己知道（启动器既不校验也不接管），所以「启动器认为已安装」与「游戏内容实际可用」之间永远隔着一层，本次只保证用户能看见它。
- 未涵盖：`CHANGELOG_RELEASE.md` 只描述当前待发布版本，本改动未随版本提交（由 `release.ps1` 在发布时纳入）。
