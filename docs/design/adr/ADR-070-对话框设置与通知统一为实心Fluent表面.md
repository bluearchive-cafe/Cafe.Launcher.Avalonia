# ADR-070：对话框、设置与通知统一为实心 Fluent 表面

- 状态：已接受
- 日期：2026-11-20
- 修订 [ADR-015](ADR-015-对话框家族v2统一框架.md) 的表面档案与尺寸律、[ADR-040](ADR-040-对话框动作按Fluent对齐顺序与默认按钮.md) 的由 [ADR-015](ADR-015-对话框家族v2统一框架.md) 继承来的宽度档，以及 [ADR-068](ADR-068-优先使用FluentAvalonia默认控件.md) 中「对话框继续使用玻璃表面」的表述。ADR-040 的动作顺序、默认按钮与焦点规则不变；ADR-056 的提交式设置语义不变。

## 背景

ADR-068 把控件模板、设置行和通知卡交给 FluentAvalonia 默认实现后，三个表面仍是 M3/玻璃时代的外壳：

- 对话框是自绘 `Border` + `Launcher.Color.Glass.Background`，在壁纸上呈半透明，配 392 / 440 / 540 三档宽度与未消费的 `Dialog.*` token；
- 设置是 960×620 的玻璃叠层，语义上是「对话框里再开一个对话框」；
- 通知是 `FAInfoBar` 内容套在玻璃卡里，与 Fluent 的语义底色不一致。

这三处同时违反两条 Fluent 规则：持久表面应保持安静，材质只服务层级与临时界面；同一界面里不要叠加多层半透明材质。主壳已经用壁纸承担了唯一的大面积材质。

## 决策

1. **材质分层**。主壳保留壁纸与半透明表面（图标栏、资讯、任务卡；玻璃模糊由 [ADR-072](ADR-072-撤销玻璃子系统并回归半透明实底.md) 撤销，本条的实心对话框/设置/通知决定不变）。对话框、设置、通知改为实心中性表面，使用 `Launcher.Color.Dialog.Background`、`Layer/*` 与 Fluent 语义底色；壁纸不再透过对话框。
2. **对话框**。保留 `DialogSurface` 与 Basic / Panel 两形态，保留模态栈、ESC、焦点归还与遮罩拦截。表面为实心 + 1 DIP 描边 + 8 DIP 圆角 + `Launcher.Elevation.Shadow.Dialog` 双层阴影。宽度收敛为**确认 440 DIP、内容型 560 DIP** 两档，删除 `short-confirmation` 特例；日志查看器 720、资源面板 720、调试面板 720、设计画廊 1000 属**面板**，不参与该宽度律。
3. **设置**。从 960×620 叠层改为**标题栏以下、图标栏右侧的整窗页面**：保留 64 DIP 图标栏与齿轮选中态（任务角标常驻可见），分类导航 216 DIP，正文独立滚动，页脚跨内容列。行形态为**分组卡片 + 原生单选组**；`Segmented.axaml` 不再恢复，`Launcher.Component.Segmented.*` 与 `.segment-*` 退场。保留草稿 + 保存与脏态确认，底栏「取消」改称「放弃更改」；「预览主界面」沿用隐藏页面 + 返回条。
4. **通知**。仍为应用内右上角 392 DIP 通知栈与固定档位时长，卡片改用 `FAInfoBar` 的实心语义底色与同色 1 DIP 描边。最多 4 条；超出时淘汰最早且**没有动作**的通知。调用方可选提供 `key` 做同类合并计数，未提供则不合并。本轮不引入 Windows 系统通知；接口收窄为 `INotificationService`，模型预留 `key` 与策略字段，切换系统通知时不改调用点。
5. **字阶**。引入 Fluent 角色（Body 14/20、Body Strong、Subtitle 20/28、Caption 12/16），随批次迁移；M3 角色在最后一个消费方迁走后退休。Windows 字体栈为 `Segoe UI Variable → Segoe UI → Microsoft YaHei UI`，中文回落雅黑，不内嵌字体。

## 后果

- 实施分三批：对话框、设置、通知。每批同一次提交内同步设计规范对应章节与受影响黄金基线；三处表面都过明/暗 × 四语言，设置额外过 100%/150%/200% 文字缩放与最小窗口。
- 设计规范 §3.1 的对话框宽度律与 §4.3 的表面材质按本文更新；设置与通知章节在各自批次落地时更新，避免规范描述未实现的行为。
- 接受代价：外观设置编辑时壁纸被整窗页面完全遮挡，必须依赖「预览主界面」才能评估取色与壁纸效果；这是整窗页面换取导航一致性的代价，删除该入口会让草稿模型失去可见的试看路径。
- 通知的 4 条上限与按 key 合并改变了「每次调用都新增一张卡」的旧行为；任务结果、后台失败等有动作的通知仍不自动淘汰，避免入口消失。

## 修订（2026-11-21）：通知改用中性卡 + 语义条

- 背景：整卡实心语义底色解决的是「半透明外壳在壁纸上显脏」，但副作用是四条严重级别在屏幕上堆成四块纯色矩形——这正是 M3 的语义色表达习惯，与 §1「严格 Fluent 2」的目标不符，也与 WinUI InfoBar「中性底 + 左侧语义条」的原生形态背离。
- 决策：卡片固定使用资讯级中性实心表面；严重级别只由**左缘 4 DIP 语义条**（`Launcher.Color.Info`/`Danger`/`Warning`/`Success`）与本地化的严重级别标题表达。`FAInfoBar` 仍承担标题、消息、关闭按钮与 Live 区域，以 `Severity="Informational"`、`IsIconVisible="False"` 使用；外壳改为 1 DIP `DividerStrokeColorDefaultBrush` 中性描边。
- 行为契约全部不变：右上角、392 DIP、栈上限 4 条、同 key 合并、`Brief/Medium/Extended` = 4/6/8 秒、悬停与聚焦暂停、有动作不自动消失、动作执行中不定进度。
- 实施期约束（记录为代价）：
  - 通知卡**不得**通过 `/template/` 选择器改模板部件（`ProductMarkup_UsesFluentControlTemplates` 拦截），因此不能把模板底色按严重级覆盖成透明；改为把 `FAInfoBar` 固定到资讯级。
  - `BoxShadow` 的 Setter 无法消费字符串型阴影资源（Avalonia 12.1.1 `InvalidCastException`），而魔法值被 token 契约拦截；通知卡因此**只用描边表达高度**，不加阴影。
  - 消息截断需要改模板 `TextBlock#Message`，同样被 `/template/` 禁则挡住，本轮**不实现 3 行截断**；长度仍由调用方负责，失败类消息应写成「结论 + 查看日志按钮」。
- 后果：`InfoBarInformationalSeverityBackgroundBrush` 覆盖继续保留（其它应用内 InfoBar 仍在用），不再需要按严重级给卡片外框描同色边。
